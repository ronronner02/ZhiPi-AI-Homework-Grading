# 团队介绍与分工

## 一、团队概况

本团队由三名工科硕士研究生组成，专业背景覆盖**机械工程、电子信息、计算机科学**，恰好对应《智批π》系统的三条技术主线：

```text
理科场景建模（机械工程）→ 识别与流程链路（电子信息）→ 系统工程实现（计算机）
```

| 成员 | 院校 | 专业 | 角色 |
| ---- | ---- | ---- | ---- |
| 成员 A | 汕头大学 | 机械工程 | 场景与算法负责人 |
| 成员 B | 中山大学 | 电子信息 | 识别与流程负责人 |
| 成员 C | 西安电子科技大学 | 计算机 | 系统工程负责人 |

## 二、成员分工

### 成员 A（汕头大学，机械工程）—— 场景与算法

理工科建模训练使其对"过程题的解题链路"有天然敏感度，负责把教学场景翻译为可计算的批改规则：

1. 理科过程题场景设计（数学/物理主打场景）；
2. 物理/数学错因标签体系与评分 Rubric 设计；
3. 过程级评分逻辑（批改节点拆解：题意理解 → 公式选择 → 数值代入 → 单位检查 → 最终答案）；
4. AI 批改 Prompt 设计与调优；
5. 批改样例集与测试数据建设；
6. 技术方案答辩。

### 成员 B（中山大学，电子信息）—— 识别与流程

信号与图像处理背景直接对口作业图像链路与系统流程控制：

1. 图像预处理与版面分析（去阴影、透视矫正、区域分割）；
2. OCR / 公式 / 图形多模态识别链路选型与调优；
3. 红黄绿置信度分流机制实现；
4. 批改任务状态机与流程自动化；
5. 学情分析流程与数据看板逻辑；
6. 识别与批改质量评测。

### 成员 C（西安电子科技大学，计算机）—— 系统工程

软件工程能力保障系统从原型到可演示产品的落地：

1. 前后端开发（学生端 / 教师端 / 管理端）；
2. 数据库设计；
3. API 实现；
4. OCR / LLM 接口接入；
5. Demo 系统部署；
6. 工程质量与性能保障。

## 三、协作机制

1. **主线推进**：按详细设计方案 §17 的四阶段 MVP 计划推进（方案与样例 → 基础系统 → 核心创新功能 → 路演包装）；
2. **接口先行**：三人以 API 契约（设计方案 §14）与数据结构（§9.3、§10）为协作边界，并行开发；
3. **每周两次同步会**：一次对齐进度与阻塞，一次做批改质量联合评审（抽样核对 AI 批改与人工判断的一致性）；
4. **质量守门**：任何 AI 判分规则改动，须通过批改样例回归集（samples/）验证后合入。

## 四、团队与命题的匹配度

1. 命题主打的"过程分""知识点薄弱分析"恰是理科过程题批改的核心难点，成员 A 的理科建模背景可以把物理/数学解题链路拆解为可评分节点；
2. 手写作业识别的成像质量、版面分割、置信度评估是典型的信号处理问题，为成员 B 的专业主场；
3. 系统需要完整的多端产品与 AI 工程链路，成员 C 具备全栈与部署能力；
4. 三人均为在读研究生，有充足投入时间与长期迭代意愿。
