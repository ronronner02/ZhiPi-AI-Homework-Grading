# 《智批π》详细设计方案

## 面向 K12 多学科作业的教师可控 AI 批改与错因诊断系统

## 1. 项目定位

### 1.1 项目名称

**智批π：教师可控的多模态作业批改与错因诊断系统**

### 1.2 一句话介绍

面向 K12 数学、物理、英语等作业场景，系统通过多模态识别、过程级批改、错因归因、教师审核和学习画像，帮助教师从重复性批改中解放出来，让每个学生获得有依据、可理解、可持续跟踪的个性化反馈。

### 1.3 核心定位

本项目不是单纯的“AI 自动批改系统”，而是：

**AI 错因诊断系统 + 教师可控批改工作台 + 学生学习画像 + 班级教学闭环平台。**

普通 AI 批改系统解决的是：

> 这道题对不对？

本项目要解决的是：

> 学生为什么错？错在哪里？老师是否信任这个判断？下一步该怎么补？下节课该怎么教？

------

## 2. 选题背景与机会

希沃现有 AI 授课助手已经覆盖多学科教学流程，支持课件、板书、图形、公式、文字、试卷题目等内容识别，也覆盖智能切题、自动批改、相似题推荐、知识讲解、习题讲评和课堂互动等场景。 希沃教学大模型也已经具备基于学科知识库生成教学资料、公式/函数/单词卡/汉字卡识别、自动切割题目并生成讲解板、撰写学生评语等能力。

这说明，如果参赛方案只是做：

> OCR 识别 → AI 批改 → 自动评语 → 知识点分析

会比较普通，因为这些已经接近现有产品能力或行业常规能力。

真正有价值的突破点应该是：

1. **从“结果判分”升级为“过程诊断”**；
2. **从“AI 直接裁决”升级为“教师可控审核”**；
3. **从“单次作业报告”升级为“长期错因画像”**；
4. **从“作业批完结束”升级为“讲解、补救、复测闭环”**。

已有研究也说明，AI 可以用于手写数学答案的初步评分，但仍然需要后续人工验证；同时，置信度机制对于建立可信批改应用非常重要。 另有研究指出，即使多模态模型用于手写数学评分，准确性在真实场景中仍不足以完全自动化，因此必须保留人工审核和评分规则约束。

因此，本方案的核心不是宣称“完全替代老师”，而是设计一个更可靠、更可控、更符合教育场景的 AI 批改系统。

## 3. 用户痛点分析

### 3.1 教师痛点

教师每天面对大量作业，主要问题不是“不想批改”，而是：

1. **重复性批改耗时长**
   客观题、计算题、常规步骤判断占用大量时间。
2. **过程题批改复杂**
   数学、物理等理科题不仅看最终答案，还要看公式、步骤、单位、图形、推理链。
3. **个性化反馈难以规模化**
   老师知道每个学生问题不同，但很难给每个人写具体评语。
4. **班级薄弱点难以快速归纳**
   批完作业后，老师往往只能凭经验判断“哪里错得多”，缺少结构化数据支持。
5. **AI 结果不完全可信**
   如果 AI 误判，老师反而需要返工，因此教师更需要“可审核、可解释、可追责”的 AI。

### 3.2 学生痛点

学生看到的反馈常常只有：

> 错了、扣分、重做。

但学生真正需要的是：

1. 我到底是哪一步错了？
2. 我是概念不会，还是计算粗心？
3. 我该先补哪个知识点？
4. 我有没有进步？
5. 老师是否真的看到了我的问题？

### 3.3 学校与教研管理痛点

学校和年级组需要知道：

1. 班级整体薄弱知识点是什么；
2. 哪些题目区分度高；
3. 哪些学生需要重点关注；
4. 哪类错误反复出现；
5. 教师后续讲评是否有效。

## 4. 目标用户与应用场景

### 4.1 目标用户

| 用户类型      | 核心需求                                 |
| ------------- | ---------------------------------------- |
| 学科教师      | 减少重复批改、快速定位错因、生成讲评建议 |
| 学生          | 获得具体、个性化、可理解的学习反馈       |
| 班主任/年级组 | 掌握班级学情、发现共性问题               |
| 教研负责人    | 追踪知识点掌握情况、优化教学安排         |
| 家长          | 理解孩子问题，不只看分数                 |

### 4.2 首期聚焦场景

虽然题目要求多学科，但 Demo 不建议一开始做全学科。首期应该聚焦：

**初中数学 + 初中物理 + 英语短答/作文片段。**

其中主打场景是：

**数学/物理理科过程题批改。**

理由：

1. 理科过程题最能体现“步骤级批改”价值；
2. 最终答案不等于真实掌握；
3. 错因可分类：公式错、单位错、概念错、图像理解错、计算错；
4. 能发挥团队中机械工程、电子信息、计算机三个专业的组合优势；
5. 比赛 Demo 更容易展示技术深度。

## 5. 产品总体目标

### 5.1 基础目标

系统可以完成：

1. 学生上传作业图片；
2. 自动识别题目与答案区域；
3. 自动批改客观题、计算题、短答题；
4. 生成个性化评语；
5. 分析学生薄弱知识点；
6. 输出班级学情报告。

### 5.2 高阶目标

系统进一步实现：

1. **步骤级证据链批改**
   不只判断对错，还定位哪一步错、为什么错。
2. **错因归因体系**
   将错误分为概念错、公式错、计算错、单位错、审题错、图形理解错、表达不完整等。
3. **红黄绿置信度分流**
   AI 高置信度自动批，中置信度教师确认，低置信度交给老师人工判断。
4. **教师可控审核**
   教师可以一键确认、修改分数、修改评语、调整错因标签。
5. **学生长期错因画像**
   持续记录学生错因变化，形成个性化补救建议。
6. **教学闭环 Agent**
   批改后自动生成下一节课讲评重点、补救练习和复测题。

### 5.3 命题要求覆盖对照

| 命题要求 | 本方案对应设计 |
| -------- | -------------- |
| 多学科支持（至少 2 个学科） | 首期覆盖初中数学、初中物理，并包含英语短答/作文评改（§4.2、§11.2） |
| 手写体识别（公式、汉字、英文） | 图像预处理 + OCR/公式/图形多模态识别链路（§9.1、§9.2） |
| 智能判分（识别部分正确的解题过程并给过程分） | Rubric 逐项评分 + 步骤级证据链批改（§6 创新点一、§9.4、§9.5） |
| 个性化评语生成 | 基于错因标签与学生画像的评语生成策略（§9.5、§15.2） |
| 知识点薄弱分析与学情报告 | 两层标签体系 + 学生长期画像 + 班级学情看板（§6 创新点三/四/五、§8.2） |
| 交付：可运行 Demo / 批改样例 / 技术说明文档 | Demo 设计（§11）、批改样例库（samples/）、技术说明文档（docs/04） |

## 6. 核心创新点设计

## 创新点一：过程级可解释批改

### 6.1 问题

传统 AI 批改系统通常只判断：

> 答案是否正确。

但数学、物理过程题更重要的是：

> 学生的推理过程是否正确。

例如一道物理题，学生最终答案错了，可能有多种原因：

1. 公式选错；
2. 单位换算错；
3. 受力分析错；
4. 电路等效关系错；
5. 代入数值错；
6. 计算粗心；
7. 表达不完整。

如果系统只说“答案错误”，教育价值很低。

### 6.2 设计方案

系统将每道理科题拆成多个批改节点：

```text
题意理解
→ 知识点识别
→ 公式选择
→ 解题步骤
→ 数值代入
→ 单位检查
→ 最终答案
```

每个节点输出：

1. 是否正确；
2. 错误位置；
3. 错误原因；
4. 对应知识点；
5. 扣分建议；
6. AI 判断依据；
7. 置信度。

### 6.3 示例

学生作答：

```text
v = s / t = 200 / 20 = 10 km/s
```

系统诊断：

```text
最终数值计算正确，但单位错误。
题目中 s = 200 m，t = 20 s，因此 v = 10 m/s。
学生将单位误写为 km/s，属于“单位表达错误”。
建议扣 1 分，并提示学生统一单位后再计算。
```

### 6.4 价值

这使 AI 从“判题机器”变成“诊断助手”，能真正帮助学生理解错误。

------

## 创新点二：红黄绿置信度分流机制

### 6.5 问题

教育场景不能容忍 AI 大规模误判。尤其是主观题、过程题、图形题，AI 如果没有把握，应该主动交给老师，而不是强行给结论。

### 6.6 设计方案

系统对每道题输出置信度，并分为三类：

| 等级 | 含义     | 处理方式                        |
| ---- | -------- | ------------------------------- |
| 绿色 | 高置信度 | AI 自动批改，老师可抽查         |
| 黄色 | 中置信度 | AI 给出建议，老师一键确认       |
| 红色 | 低置信度 | AI 不直接判分，交给老师人工批改 |

### 6.7 置信度来源

置信度由多个因素综合决定：

1. OCR 识别清晰度；
2. 题型复杂度；
3. 答案匹配程度；
4. 评分规则覆盖度；
5. LLM 自检一致性；
6. 多模型交叉验证结果；
7. 历史教师修改率。

### 6.8 示例

```text
题目：几何证明题
学生答案：手写模糊，图形辅助线不清晰
AI 置信度：42%
系统处理：标记为红色，交由老师人工判断
```

### 6.9 价值

这个机制不是炫技，而是教育产品落地的关键。它表明系统尊重教师的最终判断权，避免“AI 一票裁决”。

------

## 创新点三：错因标签体系

### 6.10 问题

普通知识点分析只能告诉老师：

> 学生哪个知识点错得多。

但它不能告诉老师：

> 学生为什么错。

例如同样是“欧姆定律”错误，可能有三种完全不同原因：

1. 不理解公式；
2. 单位换算错误；
3. 串并联电路识别错误。

这三种问题的补救方式完全不同。

### 6.11 设计方案

系统建立两层标签：

#### 第一层：知识点标签

例如：

```text
一次函数
二次函数
欧姆定律
牛顿第二定律
压强
浮力
动能和势能
英语时态
英语从句
```

#### 第二层：错因标签

例如：

```text
概念理解错误
公式选择错误
步骤缺失
计算错误
单位错误
审题错误
图形理解错误
符号书写错误
表达不完整
答案正确但过程不规范
```

### 6.12 示例

学生在物理电学题中出错：

```text
知识点：欧姆定律、串并联电路
错因：电路结构识别错误
系统建议：先补“串并联等效电路识别”，再练欧姆定律计算题。
```

### 6.13 价值

这比普通“知识点薄弱分析”更细，因为系统不只是知道学生哪里错，还知道学生为什么错。

------

## 创新点四：学生长期错因画像

### 6.14 问题

一次作业只能反映某一天的状态，不能说明学生长期问题。

老师真正关心的是：

1. 学生是否反复犯同一种错误；
2. 学生最近是否进步；
3. 学生是不是从“不会”变成“粗心”；
4. 哪些学生需要单独辅导。

### 6.15 设计方案

系统为每个学生建立学习画像：

```text
学生基本信息
→ 作业历史
→ 知识点掌握度
→ 高频错因
→ 最近进步点
→ 风险知识点
→ 个性化补救建议
```

### 6.16 学生画像内容

| 维度       | 示例                         |
| ---------- | ---------------------------- |
| 高频错因   | 单位错误、计算粗心、公式误用 |
| 薄弱知识点 | 二次函数图像、欧姆定律应用   |
| 进步趋势   | 最近三次作业计算错误下降     |
| 学习风险   | 同一知识点连续三次错误       |
| 补救建议   | 先做基础概念题，再做综合题   |

### 6.17 示例反馈

```text
张同学最近三次物理作业中，欧姆定律相关题目正确率从 40% 提升到 70%，说明公式理解已有改善。但单位换算错误仍然频繁出现，建议下一轮练习重点安排“电流、电压、电阻单位换算”专项题。
```

### 6.18 价值

这让系统真正回应题目中的核心表达：

> 每个学生都被认真对待。

------

## 创新点五：班级薄弱点热力图与教学闭环

### 6.19 问题

老师批完作业后，还要准备讲评课。但传统流程中，老师往往需要手动统计：

1. 哪道题错得最多；
2. 哪个知识点最薄弱；
3. 哪些学生属于同类问题；
4. 下一节课应该讲什么；
5. 是否需要补充练习。

### 6.20 设计方案

系统自动生成班级学情看板：

1. 班级知识点掌握热力图；
2. 错因分布图；
3. 高风险学生列表；
4. 题目区分度分析；
5. 下一节课讲评建议；
6. 自动生成补救练习；
7. 复测题推荐。

### 6.21 教学闭环

```text
作业提交
→ AI 批改
→ 错因聚类
→ 班级薄弱点分析
→ 生成讲评建议
→ 推荐补救练习
→ 下次作业复测
→ 更新学生画像
```

### 6.22 示例

系统发现：

```text
全班 62% 学生在“二次函数顶点坐标”题目中出错。
其中 70% 的错误属于“图像平移理解错误”，不是公式记忆错误。
```

系统生成讲评建议：

```text
下节课建议先用图像动态平移演示顶点变化，再讲公式推导，最后安排 3 道由图像反推解析式的练习。
```

### 6.23 价值

这让系统从“批改工具”升级为“教学决策助手”。

## 7. 系统总体架构

### 7.1 总体流程

```text
学生上传作业图片
→ 图像预处理
→ 作业区域检测
→ 题目/答案分割
→ OCR/公式/图形识别
→ 题目结构化
→ 标准答案与评分规则匹配
→ LLM 过程级批改
→ 错因标签生成
→ 置信度评估
→ 教师审核
→ 学生反馈生成
→ 班级学情分析
→ 补救练习推荐
```

### 7.2 系统架构分层

```text
前端交互层
  ├─ 学生端
  ├─ 教师端
  └─ 管理端

业务服务层
  ├─ 作业管理服务
  ├─ 批改任务服务
  ├─ 教师审核服务
  ├─ 学生画像服务
  └─ 学情分析服务

AI 能力层
  ├─ OCR 识别
  ├─ 公式识别
  ├─ 图形/版面分析
  ├─ LLM 批改
  ├─ 错因归因
  ├─ 评语生成
  └─ 置信度评估

知识与数据层
  ├─ 学科知识库
  ├─ 题库
  ├─ 评分 Rubric 库
  ├─ 学生作业库
  ├─ 错因标签库
  └─ 教师修正记录库
```

## 8. 功能模块设计

## 8.1 学生端

### 功能一：作业上传

学生可以：

1. 拍照上传；
2. 扫描上传；
3. 上传 PDF；
4. 选择学科和作业类型；
5. 查看提交状态。

### 功能二：批改结果查看

学生可以看到：

1. 每道题得分；
2. 错误步骤；
3. 错因解释；
4. 正确解法；
5. 个性化评语；
6. 推荐练习。

### 功能三：个人错题本

系统自动整理：

1. 错题原图；
2. 正确答案；
3. 我的错误步骤；
4. 错因标签；
5. 推荐复习时间；
6. 相似练习题。

### 功能四：学习画像

学生可以看到：

1. 本周掌握情况；
2. 高频错因；
3. 进步趋势；
4. 推荐补救路径；
5. 学习鼓励。

------

## 8.2 教师端

### 功能一：作业发布与收取

教师可以：

1. 创建作业；
2. 绑定班级；
3. 设置学科；
4. 上传标准答案；
5. 设置评分规则；
6. 查看提交进度。

### 功能二：AI 批改工作台

教师可以查看：

1. AI 批改结果；
2. 每道题置信度；
3. 红黄绿分流状态；
4. 错误步骤定位；
5. 错因标签；
6. 扣分依据。

### 功能三：教师审核

教师可以：

1. 一键确认 AI 结果；
2. 修改得分；
3. 修改错因标签；
4. 修改评语；

## 9. AI 技术路线

## 9.1 图像预处理

目标是提升作业图片质量。

处理内容：

1. 去阴影；
2. 自动裁边；
3. 透视矫正；
4. 去噪；
5. 增强对比度；
6. 检测手写区域；
7. 分离题干与答案区域。

可选技术：

1. OpenCV；
2. 文档矫正模型；
3. OCR 前处理算法；
4. 版面分析模型。

------

## 9.2 OCR 与多模态识别

识别对象包括：

1. 印刷体题干；
2. 手写文字；
3. 数学公式；
4. 物理单位；
5. 几何图形；
6. 电路图；
7. 受力图；
8. 英语短文。

可选工具：

1. PaddleOCR；
2. Mathpix；
3. Pix2Text；
4. Qwen-VL / GLM-4V 等国产多模态模型（优先），GPT-4o / Gemini 作为对照备选；
5. 自定义版面分割逻辑。

------

## 9.3 题目结构化

将识别内容转为结构化数据：

```json
{
  "subject": "physics",
  "grade": "middle_school",
  "question_type": "calculation",
  "question_text": "...",
  "student_answer": "...",
  "standard_answer": "...",
  "rubric": [
    {
      "step": "公式选择",
      "score": 2
    },
    {
      "step": "数值代入",
      "score": 2
    },
    {
      "step": "单位表达",
      "score": 1
    }
  ]
}
```

------

## 9.4 评分规则 Rubric

每道题最好有明确评分规则。

例如物理计算题：

| 步骤         | 分值 |
| ------------ | ---- |
| 写出正确公式 | 2    |
| 正确代入数值 | 2    |
| 计算结果正确 | 1    |
| 单位正确     | 1    |

系统不应该只让大模型自由判断，而应该让大模型按照 Rubric 逐项评分。

------

## 9.5 LLM 批改 Agent

LLM 批改 Agent 的输入：

1. 题干；
2. 标准答案；
3. 学生答案；
4. 评分规则；
5. 学科知识点；
6. 错因标签体系。

输出：

1. 总分；
2. 每步得分；
3. 错误步骤；
4. 错因标签；
5. 批改依据；
6. 学生反馈；
7. 教师备注；
8. 置信度。

------

## 9.6 错因归因模型

错因标签可以通过规则 + LLM 混合实现。

### 规则判断示例

如果最终数值正确但单位错误：

```text
错因 = 单位错误
```

如果公式错误：

```text
错因 = 公式选择错误
```

如果题目关键词理解错误：

```text
错因 = 审题错误
```

### LLM 判断示例

复杂主观题、证明题、英语表达题由 LLM 判断：

```text
请根据评分规则判断学生答案中主要错误类型，
只能从给定错因标签中选择，
并给出不超过 80 字的依据。
```

------

## 9.7 置信度评估

置信度分数可以由以下因素加权：

```text
总置信度 =
OCR 清晰度 × 0.25
+ 答案匹配度 × 0.25
+ Rubric 覆盖度 × 0.20
+ LLM 自检一致性 × 0.20
+ 历史教师通过率 × 0.10
```

分流规则：

```text
置信度 ≥ 85：绿色，自动通过
60 ≤ 置信度 < 85：黄色，教师确认
置信度 < 60：红色，人工批改
```

## 19. 风险与解决方案

### 19.1 风险一：手写识别不准确

解决方案：

1. Demo 中使用清晰样例；
2. 支持教师手动修正 OCR；
3. 对低清晰度图片标红；
4. 不强行批改模糊答案。

### 19.2 风险二：AI 批改误判

解决方案：

1. 引入 Rubric；
2. 引入置信度；
3. 引入教师审核；
4. 低置信度不自动判分；
5. 记录教师修正结果。

### 19.3 风险三：多学科范围太大

解决方案：

1. 首期主打数学/物理；
2. 英语作为扩展展示；
3. 不承诺一次性完整覆盖所有学科；
4. 强调系统架构可扩展。

### 19.4 风险四：同质化严重

解决方案：

1. 不把“自动批改”作为唯一亮点；
2. 主打过程级诊断；
3. 主打教师可控；
4. 主打错因画像；
5. 主打教学闭环。

### 19.5 风险五：数据隐私与合规

教育场景涉及未成年人个人信息与教学数据，合规是产品落地的前提。

解决方案：

1. 作业图像与学情数据脱敏存储，身份信息与作业内容分离，坚持最小化采集；
2. 遵循《个人信息保护法》《未成年人网络保护条例》，建立家长/监护人知情同意机制；
3. 大模型调用遵循《生成式人工智能服务管理暂行办法》，优先选用已备案模型或校内私有化部署；
4. AI 生成的评语与讲评内容经内容安全过滤，并由教师保留最终审核权；
5. 学情数据仅用于教学改进，提供导出与删除机制，不用于任何商业化画像。

## 21. 答辩核心话术

### 21.1 开场表达

当前很多 AI 作业系统已经可以完成自动批改和评语生成，但教育真正需要的不只是“批得快”，而是“批得准、讲得清、老师可控、学生能改”。因此我们设计了《智批π》，一个面向 K12 理科过程题的教师可控 AI 错因诊断系统。

### 21.2 核心差异化

我们的系统有四个不同点：

1. **不只看最终答案，而是分析解题步骤；**
2. **不只给分数，而是定位错因；**
3. **不让 AI 直接替代老师，而是通过红黄绿机制让老师可控审核；**
4. **不让批改停留在单次作业，而是形成学生画像和教学闭环。**

### 21.3 技术亮点表达

系统通过 OCR、多模态识别、Rubric 评分规则、LLM 批改 Agent、错因标签体系和置信度分流机制，实现作业从图像输入到错因诊断、教师审核、学生反馈和班级学情分析的完整闭环。

### 21.4 教育价值表达

我们希望 AI 不只是提高效率，而是真正帮助老师看见每个学生的具体问题，让每个学生都能收到有依据、有温度、可执行的反馈。
