## 0. Design Read（一句话读法）

**Reading this as：** K12 教师侧的「审卷 + 诊断」工作台（兼答辩 Demo 入口），受众是一线数学/物理/英语教师与评委，语言应是 **信任优先的教育产品 + 编辑部级印刷质感**，不是通用 SaaS 紫渐变，也不是纯营销落地页。

三旋钮（taste-skill dials）：

| Dial | 值 | 理由 |
|------|----|------|
| **VARIANCE** | `5` | 工作台要可预期；首屏/答辩页可略非对称，但审卷台禁止花哨 |
| **MOTION** | `3` | 教师日用高频：反馈要快，动画要克制（emil：高频操作少动画） |
| **DENSITY** | `6` | 审核列表 / 证据链 / 班级看板是数据面，需要中高密度 |

## 1. 市场与产品语境（压缩版）

### 1.1 赛道一句话

AI 作业批改已从「判对错」进入「诊断 + 教师可控 + 学情闭环」。市场不缺「批得快」，缺「批得准、讲得清、老师敢信、能沉淀」。

### 1.2 三类用户 → 三类界面压力

| 用户 | 核心任务 | 界面必须回答 |
|------|----------|--------------|
| **教师** | 少花时间审 AI 判断 | 哪份该先看？证据在哪？我怎么改？ |
| **学生** | 知道为什么错 | 错在哪一步？怎么补？ |
| **学校/教研** | 班级决策 | 共性薄弱点？高风险学生？下节课讲什么？ |

### 1.3 智批π 的差异化（UI 必须可视化的主张）

1. **过程级证据链**（不是只给总分）
2. **红黄绿置信度分流**（人机分工可见）
3. **教师终审工作台**（可改判、可校准）
4. **班级学情闭环**（批改 → 教学决策）

> UI 失败模式：把上述四点做成「装饰性 badge」，而不是可操作的工作流。

## 2. 前端术语表（沟通用）

后续改 UI 时统一用这些词，避免「那个灰条 / 左边那个框」式沟通。

### 2.1 信息架构

| 术语 | 含义 | 在本项目中的落点 |
|------|------|------------------|
| **IA（信息架构）** | 页面如何分组、命名、导航 | 四步主 Tab：提交 → 结果 → 教师台 → 看板 |
| **Primary navigation** | 全局主导航 | `.masthead` + `.tabs` |
| **Wayfinding / trail** | 引导用户下一步 | `#trail` 动线引导条 |
| **Surface hierarchy** | 背景 / 分区 / 卡片的层级 | `--paper` → `--paper-warm` → `--paper-white` sheet |
| **Viewport regions** | 屏上固定区域 | sticky masthead、sheetwrap 滚动区 |

### 2.2 布局

| 术语 | 含义 | 落点 |
|------|------|------|
| **12-column grid** | 12 栏网格 | `.gridlines` + `--cols: 12` |
| **Gutter / margin** | 栏间距 / 页边距 | `--gutter` / `--margin` |
| **Split pane** | 左右分栏 | 识别页照片 | 转写 |
| **Master–detail** | 列表 + 详情同屏 | 教师终审理想态（P0 目标） |
| **Bento** | 不对称瓷砖网格 | 看板 KPI 区可参考，禁「三等宽卡片」默认 |
| **Sticky header** | 滚动时吸顶 | `.masthead` |
| **Above the fold** | 首屏不滚动可见区 | Hero + 主 CTA |

### 2.3 组件与状态

| 术语 | 含义 | 要求 |
|------|------|------|
| **Primary / Ghost CTA** | 主按钮 / 次按钮 | 一屏最多 1 个 Primary |
| **Stamp / Badge / Tag** | 状态章 / 标签 | 红黄绿 = 分流语义，不可乱用 |
| **Skeleton** | 骨架屏 | 优于转圈 spinner（当前偏 spinner） |
| **Empty state** | 空状态 | 说明「为什么空 + 下一步做什么」 |
| **Error state** | 错误状态 | 行内说明 + 可恢复动作，禁 `alert` |
| **Loading / Progress** | 加载 / 进度 | 批量流水线要有确定进度条 |
| **Toast / Inline note** | 轻反馈 / 页内提示 | 优先 inline note，少打断 |
| **Focus ring** | 键盘焦点环 | 已有 `:focus-visible`，需保持 |
| **Touch target** | 触控热区 | ≥ 44×44 px（移动端） |
| **Affordance** | 可点击暗示 | hover / active / cursor |

### 2.4 动效（emil-design-eng 词汇）

| 术语 | 含义 | 本项目建议 |
|------|------|------------|
| **Ease-out** | 进入动画曲线 | 默认；禁 ease-in 做 UI 进入 |
| **Press feedback** | 按下缩放 | `scale(0.97)` 或 1px 位移 |
| **Stagger** | 列表错落入场 | 30–80ms；仅首次进入 |
| **Skeleton shimmer** | 骨架高光扫过 | 列表/看板加载 |
| **Reduced motion** | 减弱动效 | 已支持 `prefers-reduced-motion` |

### 2.5 业务语义（产品词，UI 必须一致）

| 词 | 含义 | 视觉约定 |
|----|------|----------|
| **绿 / 自动通过** | conf ≥ 85 | `--st-green` |
| **黄 / 教师确认** | 60–85 | `--st-yellow` |
| **红 / 转人工** | < 60 | `--st-red` |
| **转写置信 × 评分置信** | 两段可测环节 | 结果页双因子，不可合成一个「AI 分」糊弄 |
| **错因标签** | 十类枚举 | Tag，与知识点 Tag 分层 |
| **终审** | 教师改判回写 | 工作台主操作，不是弹窗玩具 |

## 3. 竞品与参考：学什么、不学什么

### 3.1 教育 / 批改赛道（功能竞品）

| 产品 | 学 | 不学 |
|------|----|------|
| **Gradescope** | 教师可控范式；Rubric 一致性；列表→详情审卷节奏；「AI 辅助、人裁决」的文案诚实 | 高校 STEM 冷色企业风；无 K12 中文手写语境；无「错因画像」叙事 |
| **科大讯飞批阅机** | 结果留痕、班级学情密度、进校信任感 | 强硬件依赖的「机柜感」；置信度分流不显性 |
| **小猿 / 作业帮** | C 端反馈即时、步骤错因表达 | 面向家长「对答案」；无教师工作台；营销感过重 |
| **希沃生态** | 校端信任、课堂闭环语汇、蓝系品牌亲和 | 官网偏硬件货架；批改深度不足——我们是增强位 |

**对智批π UI 的结论：**

- **工作台范式对齐 Gradescope**（master–detail、可裁决）
- **语义色对齐「交通灯分流」**（不是装饰）
- **品牌温度对齐希沃教育**（可信、课堂、不炫技）
- **禁止对齐 C 端「AI 学习机」的霓虹/游戏化**

### 3.2 真实产品反向学习（体验竞品，非业务竞品）

| 产品 | 可偷的结构 | 映射到智批π |
|------|------------|-------------|
| **Linear** | 极高信息密度仍清晰；键盘友好；状态色克制；列表行高与对齐偏执 | 教师审核列表、看板 KPI |
| **Notion** | 暖中性纸感、低阴影、编辑部留白、空状态友好 | 整体 canvas、sheet、empty |
| **Apple HIG / apple-design skill** | 空间一致性、按压反馈、减少无意义动画 | 按钮 active、抽屉/弹层 |
| **Sonner / Vaul 哲学（emil）** | 好默认、可打断 transition、同方向进退场 | Toast、终审面板 |

### 3.3 灵感库用法（Pinterest / Mobbin / Landingfolio）

> 三站多为会员墙/动态流，本轮以**可公开归纳的模式**+ 本机 skills 规则抽取，不依赖整页截图搬运。

#### Pinterest — 品牌与配色矿

搜词建议（后续视觉迭代用）：

- `editorial education brand` / `risograph print UI`
- `warm paper dashboard` / `teacher workspace UI`
- `exam review interface` / `grading rubric UI`
- `Swiss grid editorial web`

抽取原则：

- 要 **纸张 + 专色油墨** 的印刷感，不要渐变玻璃拟态
- 配色锁 **1 个主强调 + 语义交通灯**，不混第二套灰（暖/冷只选一边）
- 大标题靠 **字重与字距**，不靠描边渐变字

#### Mobbin — 交互与状态矿

重点临摹的模式（产品类）：

| 模式 | 典型来源产品类 | 我们用在 |
|------|----------------|----------|
| Inbox zero / triage queue | 邮件、客服、Linear | 教师待审队列 |
| Split view review | 文档批注、PR review | 原卷 | 证据 | 裁决 |
| Status filter chips | 电商订单、issue tracker | 红黄绿筛选 |
| Batch action bar | 网盘、表格 | 同错因批量确认 |
| Progress of multi-step job | 上传、导出 | 整夹批改 / 批量 OCR |
| Composed empty | 高级 SaaS onboarding | 无作业 / 无终审记录 |

#### Landingfolio — 入口与转化矿

仅用于 **Hero / 答辩入口**，不用于工作台：

| 模式 | 采用 | 拒绝 |
|------|------|------|
| 单主 CTA above the fold | ✓「开始体验完整批改动线」 | 双 CTA「了解更多」 |
| Social proof / 数字条 | ✓ 绿黄红三计数（真实业务） | 假 99.9% |
| Product UI 嵌入 Hero | ✓ 作业照片拼贴 | 虚构 3D 机器人 |
| 居中大标题 + 三等宽特性卡 | 有条件用 | 默认三卡特性墙 |

## 4. 当前 UI 现状审计（只诊断，不改代码）

### 4.1 已有家底（值得保留的方向）

现实现：`demo/static/` 零依赖 SPA；`tokens.css` 已是完整 Design Token。

| 资产 | 评价 |
|------|------|
| **Riso 编辑部方向** | 有辨识度，避开 AI 紫；与「作业纸面」隐喻同构 |
| **红黄绿语义锁** | 业务正确；文件夹刻意不用交通灯色——决策成熟 |
| **12 栏显式网格 + folio/kicker** | 答辩叙事强 |
| **focus-visible / reduced-motion** | 无障碍底线有了 |
| **四步 Tab 动线** | IA 清楚 |

### 4.2 主要问题（为什么「看起来丑 / 不专业」）

用 redesign-skill 审计维度归类：

#### A. 气质冲突

- Hero 是 **杂志封面**，工作台是 **直角油墨按钮 + 虚线 empty**，两套完成度不齐
- 系统宋/衬线栈在 **软件 UI（表单、列表、看板）** 上易显「演示稿」而非「日用工具」
- 全页 grain `z-index: 9000` 在数据密区会显脏、伤对比

#### B. 组件完成度

| 组件 | 现状 | 专业产品预期 |
|------|------|--------------|
| Loading | 虚线框 + spinner 文案 | Skeleton 对齐真实布局 |
| Empty | 单行提示 | 图标构图 + 主行动按钮 |
| Error | 分散 hint / 缺统一模式 | 行内错误 + 重试 |
| Button | 直角 + 硬阴影位移 | 可保留个性，但需统一 radius scale |
| Dialog/终审 | 偏表单弹窗 | Master–detail 同屏审卷 |
| Toast | 弱 | 非阻断反馈层 |

#### C. 响应式

- 有 900 / 860 / 760 断点，但 **手机上四 Tab + 长表单** 仍挤
- 触控热区部分 `btn--sm` 可能 < 44px
- Hero `clamp` 大标题在小屏仍可能压迫正文

#### D. 状态覆盖清单（后续改造验收用）

| 页面 | Loading | Empty | Error | 部分成功 | 权限/口令 |
|------|:---:|:---:|:---:|:---:|:---:|
| 口令门 | — | — | 口令错误 | — | ✓ 已有门 |
| 01 文件夹 | spinner | 空夹样式有 | 弱 | 批量单项失败 | — |
| 01 上传/识别 | 有进度条 | — | 弱 | 多图部分失败 | — |
| 02 结果 | 弱 | ✓ 有文案 | 弱 | — | — |
| 03 教师台 | spinner | 弱 | 弱 | 单条终审失败 | — |
| 04 看板 | spinner | 弱 | 弱 | — | — |

### 4.3 桌面 / 移动信息架构草图（沟通位置）

#### Desktop ≥ 1100px

```text
┌──────────────────────────────────────────────────────────┐
│ masthead: 品牌 | 模式章 | 重置                         │
│ tabs: 01 提交 | 02 结果 | 03 教师 | 04 看板              │
├──────────────────────────────────────────────────────────┤
│ trail（当前步提示）                                      │
├────────────────────────┬─────────────────────────────────┤
│ 主列（list / 表单）     │ 详情列（证据 / 预览）可选       │
│                        │                                 │
└────────────────────────┴─────────────────────────────────┘
```

教师台目标态（P0 文档已写）：**左队列 · 右审卷**，不要再「列表 ↔ 弹窗」来回跳。

#### Mobile ≤ 760px

```text
┌─────────────────────┐
│ 品牌 · 模式          │
│ tabs 可横滑          │
├─────────────────────┤
│ 单列 sheet 堆叠      │
│ 主 CTA 吸底（审卷时）│
└─────────────────────┘
```

- 识别 split → 上图下文
- 终审 → 全屏 sheet，而不是小 dialo

## 5. 风格决策（预告 · 细节进 DESIGN.md）

下一份 `DESIGN.md` 将沉淀为可执行 token，核心决定如下（已综合 taste / emil / 竞品 / 现有 Riso）：

1. **保留** 暖纸 canvas + 油墨字色 + 红黄绿分流（业务遗产）
2. **收敛** 软件区以无衬线 UI 为主；衬线仅用于 Hero / 章节标题
3. **降噪** grain 仅营销首屏，工作台关闭或极低
4. **补齐** skeleton / empty / error / toast 四态规范
5. **动效** 以 ease-out ≤ 200ms 反馈为主；列表 stagger 可选
6. **圆角** 引入有限 scale（现多处 0 与 8/10 混用）统一
7. **密度** 工作台 6/10，Hero 3/10
