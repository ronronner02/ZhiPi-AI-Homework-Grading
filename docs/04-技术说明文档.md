# 《智批π》技术说明文档

> 本文档面向命题交付要求中的"技术说明文档（OCR 方案、知识建模、评语生成策略）"，是《智批π：教师可控的多模态作业批改与错因诊断系统》的工程实现说明。全文以《详细设计方案》（`docs/02-详细设计方案.md`，下称"设计方案"）为唯一事实来源，凡涉及流程、标签、公式、阈值处均标注对应章节号，确保与设计方案零冲突。

## 1. 技术架构总览

### 1.1 端到端流水线

系统遵循设计方案 §7.1 的总体流程，从学生上传图像到班级学情分析形成完整闭环。端到端数据流如下：

```text
┌──────────────────────────────────────────────────────────────────────────┐
│                          智批π 端到端批改流水线                              │
└──────────────────────────────────────────────────────────────────────────┘

  学生上传作业图片
        │
        ▼
  [A] 图像预处理  ── 去阴影 / 自动裁边 / 透视矫正 / 去噪 / 对比度增强
        │
        ▼
  [B] 作业区域检测  ── 版面分析，定位题目块与作答块
        │
        ▼
  [C] 题目 / 答案分割  ── 题干区 与 手写作答区 分离
        │
        ▼
  [D] OCR / 公式 / 图形识别  ── 印刷体 + 手写 + 公式(LaTeX) + 几何/电路图语义
        │
        ▼
  [E] 题目结构化  ── 归一化为标准 JSON（见设计方案 §9.3，本文 §3.3 扩展）
        │
        ▼
  [F] 标准答案与评分规则(Rubric)匹配  ── 载入题目对应 Rubric
        │
        ▼
  [G] LLM 过程级批改  ── 七节点拆解逐项评分（见设计方案 §6.2）
        │
        ▼
  [H] 错因标签生成  ── 两层标签体系归因（见设计方案 §6.11）
        │
        ▼
  [I] 置信度评估  ── 五因子加权（见设计方案 §9.7）
        │
        ├──────────────┬──────────────────┐
        ▼              ▼                  ▼
     绿(≥85)        黄(60–85)          红(<60)
   自动通过        教师一键确认        人工批改
        │              │                  │
        └──────────────┴──────────────────┘
                       │
                       ▼
  [J] 教师审核确认  ── 改分 / 改错因 / 改评语 / 否决（见设计方案 §8.2）
                       │
                       ▼
  [K] 学生个性化反馈生成  ── 错因 + 画像驱动评语（见设计方案 §15.2，本文 §4）
                       │
                       ▼
  [L] 班级学情分析  ── 薄弱点热力图 / 错因分布 / 讲评建议（见设计方案 §6.19）

                       ▼

                       │
                       ▼
  [N] 学生长期错因画像更新  ── 回写画像库（见设计方案 §6.14）
                       │
                       ▼
```

上述流水线中，[G]→[I] 是系统技术深度所在：不是"判对错"，而是"分步骤诊断 + 可信度自评 + 分流"。教师审核 [J] 是产品落地的关键闸门，确保 AI 不做"一票裁决"（见设计方案 §6.9）。

### 1.2 系统分层

系统采用四层架构，与设计方案 §7.2 完全一致，各层职责如下：

| 层级 | 组成模块 | 核心职责 |
| ---- | -------- | -------- |
| 前端交互层 | 学生端、教师端、管理端 | 作业上传、批改结果查看、红黄绿审核工作台、学情看板 |
| 业务服务层 | 作业管理、批改任务、教师审核、学生画像、学情分析 | 任务编排、状态机流转、审核回流、画像与看板数据聚合 |
| AI 能力层 | OCR 识别、公式识别、图形/版面分析、LLM 批改、错因归因、评语生成、置信度评估 | 多模态识别与过程级批改的核心算法能力 |
| 知识与数据层 | 学科知识库、题库、评分 Rubric 库、学生作业库、错因标签库、教师修正记录库 | 知识建模、Rubric 存储、原始与结构化数据持久化 |

分层设计使"识别—批改—审核—画像"各环节解耦：AI 能力层可独立升级模型（国产模型优先，见设计方案 §13.1），业务服务层通过异步任务队列（本文 §6）串联各能力，知识与数据层沉淀教师修正数据形成持续优化闭环。

## 2. OCR 与多模态识别方案

作业图像质量参差、手写体多样、公式与图形并存，是批改准确率的第一道瓶颈。本章对应设计方案 §9.1、§9.2。

### 2.1 图像预处理流水线

预处理目标是把"随手拍"的作业照片规整为可稳定识别的标准图像，处理链路如下（对应设计方案 §9.1）：

1. **去阴影与光照均衡**：手机拍摄常见局部阴影与反光，采用背景估计（大核形态学/低频分量估计）后做除法归一化，消除不均匀光照。
2. **自动裁边与透视矫正**：基于边缘检测与最大四边形轮廓拟合定位纸张，透视变换将倾斜作业页矫正为正视图，避免手写行倾斜导致的行切分错误。
3. **去噪与二值化增强**：自适应阈值（如 Sauvola）分离笔迹与纸张纹理，保留淡色铅笔字，抑制格线/网格背景。
4. **对比度增强**：CLAHE 等局部对比度增强，提升淡墨、连笔处的可读性。
5. **版面分析**：使用版面分析模型/检测网络切分文本行、公式块、图形块（几何图、电路图、受力图），输出各区域坐标与类型标签。
6. **题目—答案区域分割**：结合版面结果与题号锚点（题号、序号、印刷体题干位置）将页面切分为"题干区（印刷体）"与"作答区（手写）"，为后续差异化识别与结构化提供依据。

工程上以 OpenCV 实现几何与滤波类算子，版面分析与区域分割调用轻量检测模型，预处理阶段全部可在本地私有化运行，不外传原图（合规考量见设计方案 §19.5）。

### 2.2 识别引擎选型对比与推荐组合

系统需同时覆盖印刷体题干、手写文字、数学公式、物理单位、几何/电路/受力图与英语短文（识别对象见设计方案 §9.2）。单一引擎难以全覆盖，故采用"专用引擎 + 多模态大模型"分工。主要候选引擎对比如下：

| 引擎 | 适用对象 | 手写与公式能力 | 部署方式 | 成本 | 许可 |
| ---- | -------- | -------------- | -------- | ---- | ---- |
| PaddleOCR | 印刷体/手写中英文文字、版面分析 | 文字识别强；手写中文中等；公式需外接 | 本地私有化，CPU/GPU 均可 | 开源免费，仅算力成本 | Apache-2.0 |
| Pix2Text | 数学公式、图文混排，输出 LaTeX/Markdown | 印刷公式强、手写公式中等；纯文字一般 | 本地私有化 | 开源免费，仅算力成本 | 开源（MIT） |
| Mathpix | 数学/手写公式转 LaTeX | 手写公式能力业界领先 | 云 API 为主 | 按量付费，境外服务 | 商业闭源（SaaS） |
| Qwen-VL | 图像整体理解、手写、公式、版面、图形语义 | 手写中英文与公式较强，具语义理解 | 云 API，可申请私有化部署 | 国产、成本可控 | 商业，已完成服务备案 |
| GLM-4V | 图像整体理解、手写、公式、图表推理 | 手写与公式较强，图文推理强 | 云 API，可私有化 | 国产、成本可控 | 商业，已完成服务备案 |

**推荐组合与理由**（遵循设计方案 §13.1"国产模型优先、可私有化部署"原则）：

- **主链路**：PaddleOCR 负责版面分析与印刷体题干、常规手写文字识别；Pix2Text 负责数学公式转 LaTeX。两者均开源、可完全本地化，构成低成本、可离线的识别底座。
- **多模态兜底与语义识别**：Qwen-VL / GLM-4V 承担复杂版面、连笔手写、公式二维结构、几何/电路/受力图的语义理解，以及手写作答的整体转写校对（本文 §5.3 交叉验证、`prompts/grading_prompts.md` Prompt 5）。国产多模态模型可申请私有化部署且已完成生成式 AI 服务备案，契合 K12 校园数据合规要求（设计方案 §19.5）。
- **境外服务仅作对照**：Mathpix、GPT-4o、Gemini 仅在离线评测中作为公式/识别精度的基准对照，不进入生产数据链路，避免学生作业数据出境。

### 2.3 手写识别难点与对策

| 难点 | 表现 | 对策 |
| ---- | ---- | ---- |
| 连笔与涂改 | 行内连写、划改、二次订正叠字 | 版面分析先做行/字切分；多模态模型整体转写并对涂改区标注不确定；不确定字符降置信度而非猜测（Prompt 5） |
| 公式二维结构 | 上下标、分式、根号、矩阵的二维空间关系 | Pix2Text/多模态输出 LaTeX 保留结构；批改前将公式规范化，避免因排版差异误判 |
| 几何图/电路图/受力图 | 辅助线、元件符号、箭头方向承载语义 | 由多模态模型输出图形的结构化语义描述（节点、连接、受力方向），交 LLM 结合题意判断，而非纯 OCR 逐字符识别 |
| 中英混排与符号 | 中英文、希腊字母、运算符、物理单位混排 | 分区识别 + 统一后处理；单位与符号建立归一化词表（如 km/s、m/s、Ω、N） |

对识别结果始终保留原图与切分坐标，供教师在审核工作台点选核对（设计方案 §8.2 功能二）。

### 2.4 识别质量评估与降级策略

识别质量直接进入置信度计算（OCR 清晰度因子，权重 0.25，见设计方案 §9.7），因此需要可量化的质量信号与明确的降级路径：

1. **识别质量信号**：综合 OCR 字符级置信度、版面切分置信度、多模态转写与专用 OCR 的一致率，归一化为 [0,1] 的"OCR 清晰度"。
2. **低清晰度标红转人工**：当清晰度低于阈值或关键作答区无法辨认时，该题置信度被拉低进入红色区间（<60），系统不强行批改，直接转教师人工判断（对应设计方案 §6.8、§19.1）。
3. **教师修正 OCR 回流再训练**：教师在审核时对识别文本的修正被记录（进入教师修正记录库，设计方案 §10.1），作为难例样本沉淀，周期性用于识别后处理规则优化与模型微调语料（本文 §5.4），形成"越用越准"的闭环。

## 3. 知识建模方案

知识建模是错因诊断与薄弱分析的骨架。系统采用"知识点体系 + 两层标签 + 题目/Rubric 结构化 + 关联图谱"四部分，对应设计方案 §6.11、§9.3、§9.4。

### 3.1 学科知识点体系

系统为每个学科维护一棵三层知识树（学科 → 知识领域 → 知识点），知识点作为第一层标签的取值域。首期覆盖初中数学、初中物理与英语写作（学科范围见设计方案 §4.2）。

**初中数学知识树（18 个知识点节点）：**

```text
初中数学
├─ 数与代数
│  ├─ 有理数运算
│  ├─ 整式与因式分解
│  ├─ 一元一次方程
│  └─ 一元二次方程
├─ 函数
│  ├─ 一次函数
│  ├─ 反比例函数
│  └─ 二次函数
├─ 图形与几何
│  ├─ 三角形全等与相似
│  ├─ 勾股定理
│  ├─ 圆的性质
│  └─ 图形的平移与旋转
└─ 统计与概率
   ├─ 数据的收集与整理
   ├─ 平均数·中位数·众数
   └─ 简单事件的概率
```

**初中物理知识树（19 个知识点节点）：**

```text
初中物理
├─ 力学
│  ├─ 速度与平均速度
│  ├─ 质量与密度
│  ├─ 牛顿运动定律（含牛顿第二定律）
│  ├─ 压强
│  ├─ 浮力
│  ├─ 功与功率
│  └─ 动能和势能
├─ 热学
│  ├─ 温度与内能
│  └─ 比热容
├─ 电学
│  ├─ 电流与电路
│  ├─ 串并联电路识别
│  ├─ 欧姆定律
│  └─ 电功率与焦耳定律
└─ 光学
   ├─ 光的反射与折射
   └─ 透镜成像
```

上述两棵树覆盖了设计方案 §6.11 所举知识点标签示例（一次函数、二次函数、欧姆定律、牛顿第二定律、压强、浮力、动能和势能等），保持一致并向下细化。

**英语写作评价维度体系**（用于英语短答/作文片段评改，五大维度）：

```text
英语写作评价体系
├─ 内容（Content）：切题与要点覆盖、观点清晰度、内容充实度
├─ 结构（Organization）：篇章结构完整、逻辑连贯与衔接、段落划分
├─ 语法（Grammar）：时态一致（英语时态）、主谓一致、从句与句式（英语从句）、标点
├─ 词汇（Vocabulary）：词汇丰富度、词汇准确性、拼写正确
└─ 书写（Handwriting）：字迹清晰、卷面整洁
```

英语维度体系同样内嵌设计方案 §6.11 所列"英语时态""英语从句"知识点，使英语作业可与数理科目共用同一套两层标签与画像机制。

### 3.2 两层标签体系

系统对每道题打两层标签（见设计方案 §6.11）：**第一层为知识点标签**（取值来自 §3.1 知识树/维度体系），回答"错在哪个知识点"；**第二层为错因标签**，回答"为什么错"。第二层错因标签枚举严格采用设计方案 §6.11 定义的十类，不增不减：

| 错因标签 | 定义 | 典型判定规则 |
| -------- | ---- | ------------ |
| 概念理解错误 | 对概念、定义、定理的理解本身有误，导致方向性错误 | 公式/方法选择错误且根源在于概念混淆（如混淆速度与加速度、混淆串并联特性）；非计算或书写层面的偏差 |
| 公式选择错误 | 选用了不适用于本题情境的公式或定理 | 标准解法要求公式 A，学生使用了不适用的公式 B；即使代入计算无误，方向已错 |
| 步骤缺失 | 解题链中缺少必要的关键步骤 | Rubric 中某得分步骤在作答中完全无对应内容（如缺受力分析、缺公式变形、缺必要辅助线说明） |
| 计算错误 | 公式与步骤正确，但数值运算出错 | 公式选择正确、代入正确，但算术/代数运算结果与正确值不符 |
| 单位错误 | 数值正确但单位缺失、写错或换算错误 | 最终数值正确而单位不符（如 10 m/s 误写为 10 km/s，见设计方案 §6.3）；或单位换算系数用错 |
| 审题错误 | 未正确理解题意或遗漏题目条件/所求 | 关键条件被忽略、所求对象理解错误、答非所问 |
| 图形理解错误 | 对几何图、电路图、受力图、函数图像的理解有误 | 电路结构识别错误、辅助线关系误判、图像平移/对称理解错误（如设计方案 §6.22 顶点坐标题） |
| 符号书写错误 | 数学/物理符号书写不规范或笔误 | 正负号、上下标、变量名笔误，未达概念错误程度，但影响正确性或规范性 |
| 表达不完整 | 结论或论述不完整，缺少必要说明/结论句 | 有过程无最终结论、证明缺少结论陈述、英语作答要点表达残缺 |
| 答案正确但过程不规范 | 最终答案正确，但过程书写不规范或跳步 | 结果正确但缺少必要步骤书写、格式不规范、跳步导致过程分受影响 |

错因标签由"规则 + LLM"混合产生：可硬判定的（如数值对而单位错 → 单位错误）优先走规则（设计方案 §9.6），复杂主观题由 LLM 从上述枚举中选择并给出不超过 80 字依据（见 `prompts/grading_prompts.md` Prompt 2）。

### 3.3 题目结构化与 Rubric 建模

题目结构化 JSON 在设计方案 §9.3 基础上扩展，兼容其全部字段（subject / grade / question_type / question_text / student_answer / standard_answer / rubric[step,score]），并补充题目标识、知识点、满分、Rubric 判分要点、标准解题步骤与补救资源引用等，形成完整 Schema：

```json
{
  "$schema": "https://json-schema.org/draft-07/schema#",
  "title": "ZhipiQuestionSchema",
  "type": "object",
  "required": ["subject", "grade", "question_type", "question_text",
               "student_answer", "standard_answer", "rubric"],
  "properties": {
    "question_id":    { "type": "string", "description": "题目唯一 ID" },
    "subject":        { "type": "string", "enum": ["math", "physics", "english"] },
    "grade":          { "type": "string", "example": "middle_school" },
    "question_type":  { "type": "string",
                        "enum": ["calculation", "proof", "short_answer",
                                 "essay", "choice", "fill_blank"] },
    "question_text":   { "type": "string", "description": "结构化题干" },
    "student_answer":  { "type": "string", "description": "识别后的学生作答（含 LaTeX）" },
    "standard_answer": { "type": "string", "description": "标准答案" },
    "max_score":       { "type": "number", "description": "本题满分" },
    "knowledge_points":{ "type": "array", "items": { "type": "string" },
                         "description": "第一层知识点标签，取值自知识树（§3.1）" },
    "difficulty":      { "type": "string", "enum": ["easy", "medium", "hard"] },
    "standard_solution_steps": {
      "type": "array", "description": "标准解题步骤，用于步骤级比对",
      "items": { "type": "object",
        "properties": { "node": { "type": "string" }, "content": { "type": "string" } } }
    },
    "rubric": {
      "type": "array",
      "description": "评分规则，兼容 §9.3 的 [{step, score}] 并扩展判分要点",
      "items": {
        "type": "object",
        "required": ["step", "score"],
        "properties": {
          "step":       { "type": "string",
                          "description": "对应批改节点，如 公式选择/数值代入/单位表达（§6.2）" },
          "score":      { "type": "number", "description": "该步分值" },
          "criteria":   { "type": "string", "description": "得分判定标准（判分要点）" },
          "key_points": { "type": "array", "items": { "type": "string" } },
          "linked_error_tags": {
            "type": "array", "items": { "type": "string" },
            "description": "该步骤失分时可能对应的错因标签（枚举见 §3.2）" }
        }
      }
    }
  }
}
```

该 Schema 是 LLM 批改 Agent 的标准输入契约：`rubric` 逐项对应设计方案 §6.2 的批改节点，`linked_error_tags` 建立"步骤失分 → 错因候选"的先验映射，约束 LLM 在既定枚举内归因，降低幻觉。

### 3.4 知识点—错因—补救资源关联建模

为支撑"补救练习推荐"与"复测题推荐"（教学闭环，见设计方案 §6.21），系统在知识与数据层建立知识图谱，核心是"知识点—错因—补救资源"三元组：

```text
三元组：(知识点 KP, 错因 ErrorTag, 补救资源 Resource)

示例：
(欧姆定律, 图形理解错误[串并联电路识别], 微课「串并联等效电路识别」+ 3 道电路结构判断题)
(二次函数, 图形理解错误[图像平移], 动态平移演示 + 3 道由图像反推解析式题)
(速度与平均速度, 单位错误, 单位换算专项讲解 + 5 道单位统一练习)
```

图结构定义如下：

- **节点类型**：知识点节点（KnowledgePoint）、错因节点（ErrorTag）、资源节点（Resource：微课/例题/复测题/知识卡）、题目节点（Question）。
- **边类型**：`知识点 --requires--> 前置知识点`（知识依赖）、`题目 --tests--> 知识点`、`(知识点,错因) --remedied_by--> 资源`、`资源 --retest_by--> 复测题`。

推荐逻辑：学生某题产生"(KP, ErrorTag)"组合后，系统沿 `remedied_by` 边召回补救资源，沿知识依赖边判断是否需先补前置知识点（如"先补串并联识别，再练欧姆定律计算"，对应设计方案 §6.12），并沿 `retest_by` 边生成下轮复测题。该图谱同时驱动学生画像的"风险知识点—补救路径"（设计方案 §6.15）与班级讲评的补救练习生成（设计方案 §6.20）。

## 4. 评语生成策略

评语是系统"温度"的体现，也是命题"个性化评语生成，而非千篇一律"的直接考核点。本章对应设计方案 §9.5、§15.2。

### 4.1 输入要素

个性化评语由四类要素共同驱动，避免"只看分数"式套话：

1. **逐题批改结果**：各题得分、失分步骤、Rubric 逐项评分（设计方案 §6.2 节点输出）。
2. **错因标签**：本次高频错因与最关键错因（两层标签，设计方案 §6.11）。
3. **历史学习画像**：既往高频错因、薄弱知识点、学习风险（设计方案 §6.16）。
4. **进步趋势**：与近几次作业对比的正确率变化、错因迁移（如"从不会变为粗心"，设计方案 §6.14）。

### 4.2 生成约束

评语生成严格遵循设计方案 §15.2 的约束，落地为可校验规则：

1. **先肯定已掌握部分**：开头必须指出学生本次做对/思路正确之处。
2. **再指出最关键问题**：只聚焦一个最关键错因，不罗列所有小错，避免打击。
3. **给可执行建议**：给出具体、可操作的下一步（如"做题前先统一单位再代入公式"），而非方向性口号。
4. **长度约束**：不超过 80 字。
5. **禁用空泛表达**：禁止"继续努力""再接再厉""加油"等无信息量套话，由敏感/套话词表在后处理阶段拦截。
6. **语气温和**：不贬损学生，对待进步给予具体肯定。

### 4.3 防模板化机制

为杜绝"千篇一律"，系统从四个维度控制评语多样性：

1. **错因驱动**：评语内容锚定该生本次的具体错因与失分步骤，天然因人而异（不同学生错因组合不同）。
2. **画像驱动**：引入历史趋势与进步点，使同样"单位错误"的两名学生因历史不同而评语不同（一个是"反复出现需专项"，一个是"较上次已改善"）。
3. **表达多样性控制**：维护句式模板池并随机化开头/建议句式，设置措辞多样性约束，避免同一批作业复用同一句式。
4. **同班去重检查**：对同一次作业的全班评语做相似度检测（文本向量相似度 + 关键短语重合度），相似度超阈值则触发重写，确保没有两份评语雷同。

### 4.4 内容安全与教师终审

评语面向未成年人，须过内容安全与教师终审双闸门（对应设计方案 §19.5）：

1. **敏感词与套话过滤**：生成后经内容安全过滤，拦截敏感、贬损、空泛词。
2. **语气校验**：校验是否含负面标签化措辞（如"笨""差生"），命中则重写。
3. **教师可改可否决**：所有评语进入教师端为草稿态，教师可一键采纳、修改或否决（设计方案 §8.2 功能三）。教师保留最终审核权，AI 不直接下发给学生。

### 4.5 对比示例（模板化 vs 本系统个性化）

以下三组对比展示"套话评语"与"错因+画像驱动评语"的差异（均 ≤80 字）：

**示例一（物理·速度与单位换算，本次单位错误、公式思路正确）**

- 模板化：`本次作业完成较好，继续努力，争取下次取得更好成绩！`
- 本系统：`速度公式选择和计算都正确，思路很清楚。唯一问题是把 m/s 写成了 km/s。下次做题前先统一单位再代入，就能拿满分。`

**示例二（数学·二次函数图像，审题正确但图像平移理解错误，较上次有进步）**

- 模板化：`还需加强练习，再接再厉。`
- 本系统：`这次你已能正确列出顶点式，比上次进步明显。主要问题在图像左右平移方向判断反了。建议对照"左加右减"口诀，再做 2 道平移题巩固。`

**示例三（英语·作文片段，内容切题、结构清晰但时态不一致）**

- 模板化：`作文写得不错，注意语法，继续加油。`
- 本系统：`文章切题、结构清楚，开头结尾都完整。最需要改的是时态：叙述过去的事时有几处用了现在时。建议通读一遍统一为一般过去时。`

对比可见：本系统评语可定位到具体步骤/维度、给出可执行动作、并结合进步趋势，从根本上区别于模板化套话。

## 5. 过程级批改与置信度分流实现

本章是系统技术核心，对应设计方案 §6.2、§9.5、§9.7。

### 5.1 LLM 批改 Agent 工作流

批改 Agent 以结构化题目（§3.3 Schema）为输入，按设计方案 §6.2 的七个批改节点逐项评分，工作流如下：

```text
① 结构化输入装配
   题干 + 标准答案 + 学生作答 + Rubric + 知识点 + 错因标签枚举（设计方案 §9.5 输入）
        │
        ▼
② 逐节点比对（题意理解→知识点识别→公式选择→解题步骤→数值代入→单位检查→最终答案）
   对每个节点输出：是否正确 / 错误位置 / 错误原因 / 对应知识点 /
                  扣分建议 / AI 判断依据 / 置信度（设计方案 §6.2）
        │
        ▼
③ 逐 Rubric 项评分（不得只看最终答案，必须按 Rubric 逐项给分，设计方案 §9.4）
        │
        ▼
④ 错因归因（从给定错因标签枚举中选择，§3.2 / 设计方案 §6.11）
        │
        ▼
⑤ 自检（一致性复核，见 §5.3）
        │
        ▼
⑥ 输出标准 JSON（score/step_analysis/knowledge_points/error_tags/
                 student_feedback/teacher_note/confidence，设计方案 §15.1）
```

Agent 输出严格遵循设计方案 §15.1 的 JSON 结构，`step_analysis` 逐步对应 Rubric，保证批改结果可解释、可核对、可回流。

### 5.2 置信度加权计算与红黄绿分流

置信度公式与权重严格沿用设计方案 §9.7，不做任何改动：

```text
总置信度 = OCR 清晰度 × 0.25
        + 答案匹配度 × 0.25
        + Rubric 覆盖度 × 0.20
        + LLM 自检一致性 × 0.20
        + 历史教师通过率 × 0.10
```

分流阈值同样沿用设计方案 §9.7：**置信度 ≥ 85 → 绿色（自动通过）；60 ≤ 置信度 < 85 → 黄色（教师确认）；置信度 < 60 → 红色（人工批改）**。

工程实现伪代码如下（各因子归一化到 [0,1]，加权后乘 100 折算为 0–100，以与 §9.7 阈值口径统一；题型复杂度与多模型交叉验证作为降级闸门，来自设计方案 §6.7）：

```python
# 权重严格取自设计方案 §9.7
WEIGHTS = {
    "ocr_clarity":          0.25,  # OCR 清晰度
    "answer_match":         0.25,  # 答案匹配度
    "rubric_coverage":      0.20,  # Rubric 覆盖度
    "llm_self_consistency": 0.20,  # LLM 自检一致性
    "teacher_pass_rate":    0.10,  # 历史教师通过率
}

HIGH_RISK_TYPES      = {"proof", "essay", "figure"}  # 证明/作文/图形题
CROSS_CHECK_TOLERANCE = 0.15  # 多模型交叉验证允许的最大分歧

def clamp01(x):
    return max(0.0, min(1.0, x))

def composite_confidence(factors: dict) -> float:
    s = sum(WEIGHTS[k] * clamp01(factors[k]) for k in WEIGHTS)
    return round(s * 100, 1)  # 折算到 0–100，口径同 §9.7 阈值

def route(conf: float, question_type: str, cross_check_gap: float) -> str:
    # 多模型分歧过大：强制转人工（设计方案 §6.7 第 6 项）
    if cross_check_gap > CROSS_CHECK_TOLERANCE:
        return "red"
    # 高风险题型不进入绿色自动通过，最高只到黄色（体现教师可控，§6.9）
    if question_type in HIGH_RISK_TYPES and conf >= 85:
        conf = 84.9
    # 阈值分流严格遵循设计方案 §9.7
    if conf >= 85:
        return "green"    # 绿色：自动通过，教师抽查
    elif conf >= 60:
        return "yellow"   # 黄色：教师一键确认
    else:
        return "red"      # 红色：人工批改
```

设计方案 §6.7 列出的"题型复杂度""多模型交叉验证"两项，不改变 §9.7 五因子加权公式本身，而作为分流闸门叠加：高风险题型即使加权分高也不自动通过，多模型分歧过大直接转人工，从而在不违背公式的前提下更稳妥地落地"教师可控"。

### 5.3 LLM 自检一致性与多模型交叉验证

"LLM 自检一致性"是 §9.7 中权重 0.20 的因子，通过两条路径获得：

1. **自检一致性**：对同一题让模型进行第二次独立批改（不看第一次结果），比对两次在总分、失分步骤、错因标签上的差异，输出一致性分（见 `prompts/grading_prompts.md` Prompt 6）。两次结论越一致，一致性分越高；分歧越大，一致性越低并拉低总置信度。
2. **多模型交叉验证**：对复杂题由不同国产模型（如 Qwen 与 GLM，设计方案 §13.1）分别批改，比较结论差异（`cross_check_gap`）。差异过大直接进入红色人工（§5.2 伪代码），差异小则增强可信度。

两条路径都体现设计方案 §6.5 的原则：**AI 没把握时主动交给老师，而非强行给结论**。

### 5.4 教师修正数据回流机制

教师审核不仅是质量闸门，更是系统持续优化的数据来源，回流机制如下（对应设计方案 §10.1 教师修正记录表、§19.2）：

```text
教师审核动作（改分 / 改错因 / 改评语 / 修正 OCR）
        │
        ▼
写入教师修正记录库（original_score/corrected_score/original_tag/corrected_tag …）
        │
        ├─► 错例库：AI 判断 ≠ 教师判断的样本，沉淀为难例
        │
        ├─► 历史教师通过率：按题型/知识点统计教师改动率，回灌 §9.7 第 5 因子
        │
        ├─► Prompt 迭代：高频误判模式转化为 Prompt 中的补充约束与反例
        │
        └─► 微调语料：难例经脱敏后作为识别/批改模型的微调与评测数据
```

该机制使"历史教师通过率"因子随使用动态更新，系统越用越贴合本校本班的评分习惯，同时为识别与批改模型提供高质量再训练数据，形成正向闭环。所有回流数据均脱敏处理，身份信息与作业内容分离（设计方案 §19.5）。

## 6. 工程落地要点

### 6.1 异步批改任务队列

一个班约 40 份作业需并发批改，识别与 LLM 调用均为耗时操作，故采用异步任务队列（技术栈见设计方案 §13.1：Celery/RQ + Redis + FastAPI）：

- **任务拆分**：一次提交拆为"预处理 → 识别 → 结构化 → 批改 → 归因 → 置信度"多级子任务，逐级流转，进度经 WebSocket 推送前端（设计方案 §13.1）。
- **状态机**：提交状态在 `待识别 → 批改中 → 待审核 → 已完成` 间流转（对应设计方案 §10.1 submissions.status），红黄绿分流结果决定进入"待审核"的题目集合。
- **并发与限流**：对 LLM/多模态 API 调用设并发上限与令牌桶限流，保护第三方与私有化推理服务，避免高峰打满。

### 6.2 失败重试与幂等

- **重试策略**：识别/LLM 调用失败按指数退避重试（如 3 次），区分可重试错误（超时、限流）与不可重试错误（图像损坏），后者直接标红转人工，不无限重试。
- **幂等设计**：以 `submission_id + question_no + 批改版本号` 作为幂等键，重复触发批改不产生重复结果、不覆盖已确认的教师修正；教师已审核题目重批时进入新版本而非覆盖终审结论，保证审核结果不被回归。
- **可观测性**：每级子任务记录耗时、模型版本、置信度分布，供质量评测与成本核算（设计方案 §18.1）。

### 6.3 单份作业成本估算方法

比赛阶段不宜编造精确单价，此处给出**估算框架**与**量级推理方法**，实际数值以选定模型的计费与实测 token 量为准：

```text
单份作业成本 ≈ Σ_题目 ( 识别成本_i + 批改成本_i + 自检/交叉验证成本_i ) + 固定处理成本

其中：
  识别成本_i        ≈ 图像 token/次数 × 多模态单价（私有化部署时折算为 GPU 摊销）
  批改成本_i        ≈ (输入 token + 输出 token) × LLM 单价
  自检/交叉验证成本_i ≈ 批改成本_i × k   （k = 自检/交叉验证触发比例，仅复杂题触发）
  固定处理成本       ≈ 预处理算力 + 存储 + 队列调度（可近似为常数）
```

**量级推理**：

1. **成本大头识别**：主要成本集中在多模态识别与 LLM 批改的 token 消耗，预处理与存储为次要项。
2. **降本杠杆**：① 简单客观题走规则/轻量 OCR，不调用大模型；② 自检与多模型交叉验证只对复杂题（高风险题型、中低置信度）触发，控制 k 值；③ 高置信度绿色题不重复批改；④ 国产模型私有化部署后，边际成本从"按 token 付费"转为"GPU 摊销 + 电力"，规模化后单份成本显著下降（设计方案 §13.1 强调国产、可私有化、成本可控）。
3. **估算流程**：先在样例集实测每类题目的平均输入/输出 token 与识别调用次数，再乘以选定模型公开计费或私有化摊销单价，按题型占比加权得到"单份作业期望成本"，并给出高峰并发下的容量与成本上界。该方法给出量级与结构，不依赖任何编造的精确价格。

## 7. 飞书 AI 产品能力集成实现

本章对应设计方案 §13.2《飞书 AI 产品能力集成设计》，落地"批改在系统、协同在飞书"原则：系统负责识别与批改，飞书承接学情沉淀、教师协同与 AI 二次加工。四个集成点中，集成点一、二已在 Demo 中以可运行代码实现（`demo/pipeline/feishu.py`，接口 `/api/feishu/sync-base`、`/api/feishu/push`），集成点三、四为入围后随企业教练搭建的能力。未配置凭据时全部走演示模式，展示"将写入的记录"与"将推送的卡片"，保证现场可演示。

### 7.1 多维表格 AI 学情台账（集成点一，主用飞书 AI 能力）

批改完成后，系统经开放平台 API 将逐题结果写入班级《学情台账》多维表格。前 8 个字段由系统写入，后 2 个由飞书 **AI 字段捷径**在表格内逐行生成，表结构如下：

| 字段 | 类型 | 来源 | 说明 |
| ---- | ---- | ---- | ---- |
| 学生 | 文本 | 系统写入 | 学生姓名 |
| 题号 | 文本 | 系统写入 | 题目 ID 与标题 |
| 得分 | 数字 | 系统写入 | 本题教师前 AI 得分 |
| 满分 | 数字 | 系统写入 | 本题满分 |
| 错因标签 | 多选/文本 | 系统写入 | 取自设计方案 §6.11 十类错因枚举 |
| 置信度 | 数字 | 系统写入 | §9.7 五因子加权结果 |
| 分流状态 | 单选 | 系统写入 | 红/黄/绿（§6.6） |
| 教师终审 | 文本 | 系统写入 | 教师确认/修改动作与终分 |
| 一句话错因摘要 | **AI 字段捷径** | 飞书 AI 生成 | 见下方提示词要点 |
| 个性化学习建议 | **AI 字段捷径** | 飞书 AI 生成 | 见下方提示词要点 |

**AI 字段捷径配置**（在多维表格内对上述列配置，无需系统侧再调大模型）：

- **一句话错因摘要**字段：提示词要点为"依据本行【错因标签】与【分流状态】，用不超过 30 字客观概括该生本题主要问题，只陈述错在何处、不作评价"；
- **个性化学习建议**字段：提示词要点为"依据本行【错因标签】与【得分】/【满分】，给出一条具体、可执行的补救建议（先补哪个知识点、做几道何种练习），不超过 40 字，语气温和，禁用'继续努力'等空泛套话（§15.2 约束）"。

**仪表盘用法**：基于该表建多维表格仪表盘——按「分流状态」出红黄绿占比饼图、按「错因标签」出错因分布柱状图、按「题号/知识点」透视错误率，等价于把设计方案 §6.19、§6.20 的班级薄弱点热力图与错因分布搬进飞书，教研组无需登录系统即可在飞书内查看与协作，学情以结构化资产沉淀在学校自有飞书空间。

### 7.2 机器人互动卡片审核流转（集成点二）

**Webhook 接入**：在教师群添加飞书自定义机器人，取其 Webhook 地址注入环境变量 `ZHIPI_FEISHU_WEBHOOK`，系统以 `msg_type=interactive` 向该地址 POST 卡片消息，无需应用鉴权，接入成本最低，适合现场演示。

**卡片结构**：`header`（标题「作业批改完成·待审核提醒」）+ 概览区（作业名、参与作答人数、平均得分率）+ 红黄绿分流统计 + 醒目的「待教师处理」数量（黄+红）+ 主要错因（错因分布前三）+ `action` 按钮「前往审核工作台」（占位跳转链接，经 `ZHIPI_REVIEW_CONSOLE_URL` 注入本校地址）+ 落款 `note`。

**审核流转闭环**：卡片提醒 → 教师点按钮跳转红黄绿审核工作台（§8.2 功能三）→ 一键确认/修改分数与错因 → 终审结果回写系统并可再同步台账；教师终审后还可选择向家长推送个性化评语卡片，支撑家校沟通（设计方案 §13.2 集成点二第 2 条）。由此「批改—提醒—审核—反馈」在飞书侧闭环，且始终由教师持最终裁决权（§6.9）。

### 7.3 知识问答 / Aily 讲评助手（集成点三）与文档 AI（集成点四）

**知识库沉淀清单**：将三类结构化知识沉淀入飞书知识库——① 两层标签体系（知识点标签 + §6.11 十类错因标签）；② 各题评分 Rubric（§9.4）与标准解题步骤；③ 历次班级学情报告与典型错例、讲评提纲（§6.19、§6.20）。

**教师问答场景示例**：教师在飞书内向「讲评助手」提问"本次欧姆定律作业主要错因是什么？下节课该怎么讲？"，助手基于上述知识库中的错因分布与 Rubric 给出有据回答，而非泛化生成（设计方案 §13.2 集成点三第 2 条）。

**Aily / 妙搭搭建路径**：入围后配合企业教练，用飞书 **Aily** 智能体开发平台把"讲评课提纲生成"（§8.2 功能五、§15.3 教学建议 Prompt）搭建为正式智能体应用，挂接知识库做检索增强；用 **妙搭** 低代码搭建教师端轻应用，直接读写 7.1 的多维表格台账。集成点四则把讲评建议一键导出为飞书文档并用文档 AI 润色排版，供教研组协作批注（设计方案 §13.2 集成点四）。

### 7.4 开放平台鉴权与写表要点

集成点一的真实写表走飞书开放平台自建应用链路，工程要点如下：

1. **鉴权（tenant_access_token）**：以 `app_id` + `app_secret` POST `/open-apis/auth/v3/tenant_access_token/internal` 换取 `tenant_access_token`（有效期约 2 小时）。生产环境应缓存复用、临期前刷新，避免每次写表都重新申请。
2. **批量写入（batch_create）**：以 `Authorization: Bearer {token}` POST `/open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records/batch_create`，请求体为 `{"records":[{"fields":{...}}]}`，单次最多 500 条；`fields` 键名须与表列名完全一致，单选/多选列的值需为选项名/数组。
3. **频控与重试**：开放平台对接口有 QPS 频控，命中限流（HTTP 429 或频控错误码）时按指数退避重试，超 500 条按 ≤500 分片提交；区分可重试错误（超时、限流）与不可重试错误（字段不匹配、鉴权失效）。
4. **失败降级**：鉴权、频控或写表任一失败，`sync_to_base` 自动降级为演示模式并返回将写入的记录（实现见 `demo/pipeline/feishu.py`），保证 Demo 现场不中断，与批改主链路"LLM 失败降级 mock"（§5.3）保持一致的稳健策略。
