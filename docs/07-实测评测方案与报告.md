## 1. 评测目的与问题

系统的核心宣称是「过程级批改 + 置信度红黄绿分流 + 教师终审」（详见 `docs/04-技术说明文档.md` §5–§6）。这些宣称是否成立，归结为评委必问的三个问题：

| # | 评委之问 | 对应指标（§3） | 结果表（§5） |
| --- | --- | --- | --- |
| Q1 | **AI 批改与教师判分的一致率是多少？** | 总分一致率、MAE、Pearson r、Cohen's kappa、错因标签命中率 | 表 B、表 C、表 E |
| Q2 | **绿桶（自动通过）的准确率是多少？红黄绿分流是否校准？** | 分桶教师认可率（绿 / 黄 / 红三行） | 表 D |
| Q3 | **相比纯人工批改，教师实际省时多少？** | 省时率（人工计时对比） | 表 F |
| Q0 | （前置）手写识别本身可靠吗？ | OCR 字符错误率 CER | 表 A |

Q0 是 Q1–Q3 的前置：转写错了，批改无从谈起，因此 OCR 单独评测并单独报告。

## 2. 评测集构成

### 2.1 采集规范（目标 30–50 份真实手写作答）

| 维度 | 规范 |
| --- | --- |
| 总量 | 30–50 份真实学生手写作答（1 份 = 1 题 1 人次作答） |
| 学科分布 | 数学、物理、英语各 **≥ 10 份**，与题库三科（`demo/data/questions.json`，可经评测集 `questions.json` 扩题）对应 |
| 卷面分层 | 按卷面质量分三档：**工整 / 潦草 / 涂改**，各档约占 1/3，采集时在台账中登记档位，避免只收「好认的卷子」抬高指标 |
| 作答水平 | 覆盖满分卷、部分失分卷与低分卷，不得只采集正确作答 |
| 拍照规范 | 手机自然俯拍：光照均匀无强反光、纸面完整入镜、长边分辨率 ≥ 1600px、不加滤镜不做美化；允许轻微倾斜与阴影（贴近教师真实使用场景，不做「摆拍级」预处理） |
| 隐私合规 | 拍摄前遮盖 / 裁除学生姓名与学号，评测集内以匿名 `item_id` 标识；采集获得授课教师与学生监护人知情同意，数据仅用于本次评测，不入库不外传 |

### 2.2 人工标注规范（双评 + 仲裁）

人工判分是本评测的「参照标准」，其本身的质量必须有程序保证：

1. **人工校对转写**：由标注者对照原卷逐字校对，形成 `ocr_text_human`（CER 评测的参照文本）。看不清的字符经两人合议后定字，仍无法辨认的以〔?〕记录。
2. **双评盲评**：2 名评分者（记 T1、T2）依据该题 Rubric（口径同设计方案 §9.4）**独立**判分并标注错因（错因标签限设计方案 §6.11 十类枚举）。**双评者资质如实声明：为团队成员，非在职教师**（该局限的影响见 §7 第 5 条）。正式判分前，两人先在评测集之外的 3–5 份练习作答上**依 Rubric 逐步校准评分口径**（对齐每步给分 / 部分分标准），校准完成后进入独立判分，判分期间不再互通。双评期间**不得查看 AI 批改结果**，防止锚定偏差。
3. **分歧仲裁**：双评总分差 > 满分 × 10%，或错因标签集合不一致时，由第三人主持三人合议，形成终判分 `human_score` 与终判错因 `human_error_tags`；终判前不得参考 AI 结果。
4. **保留原始分并记录双评者间一致性**：T1 与 T2 的判分一致率与 kappa 按各自**原始分**单独统计（表 B 附行），作为「人与人之间本来能达到的一致性参照」，供解读 AI—人一致率时对照（§6 规则 R6）。**对照的对称性约束（预注册）**：仲裁共识分经双评合议平滑，天然比任一单评更「稳」；若拿「AI vs 共识分」的一致率去与「T1 vs T2 原始互评」的一致率比较，两侧口径不对称，统计上偏向 AI。因此凡与人—人一致性对照的比较，一律使用「AI vs T1」「AI vs T2」（AI 对各评者**原始分**）两个一致率的**均值**，与「T1 vs T2」做同口径对比（§5 表 B 增列两行，判定规则见 R6）；仲裁共识分 `human_score` 仅用于表 B 主行（AI vs 教师终判）与分桶认可率（表 D）等口径。

标注结果按 `eval_harness.py` 模块 docstring 约定写入 `manifest.json`（字段：`item_id / question_id / image / ocr_text_human / human_score / human_error_tags / human_grader`）；在此基础上 manifest **必须同时保留双评各自的原始分数字段 `human_score_t1` / `human_score_t2`**（仲裁共识分仍为 `human_score`，不被覆盖），供表 B 的「AI vs T1」「AI vs T2」「T1 vs T2」各行按 §3.2 同一带宽计算（harness 未直接输出的行，由 `report_data.json` 逐条明细联合 manifest 该两字段汇总）。

## 3. 指标定义（口径与 `eval_harness.py` 完全一致）

以下所有口径以 `demo/tools/eval_harness.py` 中常量与函数为准，文档与代码不一致时以代码为准并修订文档。

### 3.1 OCR 字符错误率 CER

```text
CER = Levenshtein(机器转写, 人工转写) / len(人工转写)
```

- 编辑距离为经典 Levenshtein（插入 / 删除 / 替换各计 1，自实现，见 `levenshtein()`）；
- **主口径（去空白）**：比较前去除全部空白字符（空格 / 换行 / 制表），拍照转写的排版差异不计错；
- **严格口径**：仅统一换行符，其余原样比较。两口径同时报告；
- 机器转写来自 `pipeline.ocr.recognize_vlm`（与线上批改链路同一引擎、同一 Prompt），需配置 `ZHIPI_VLM_API_KEY`。

### 3.2 批改一致性

对每条评测条目，AI 分 `s_ai` 来自 `pipeline.grader.grade_adhoc`（真实 LLM 批改，与线上图片批改链路同源；无 Key 时该项整体跳过，**不用 mock 结果冒充实测**），教师分 `s_h` 为 §2.2 终判分：

```text
MAE        = (1/n) Σ |s_ai − s_h|                       （单位：分）
总分一致率  = #{ |s_ai − s_h| ≤ 满分 × 10% } / n         （含等号）
Pearson r  = AI 分与教师分的皮尔逊相关系数（n<2 或方差为 0 时记「不可计算」）
```

「满分 × 10%」为**预先固定**的一致判定带宽（代码常量 `AGREE_RATIO = 0.10`），对 10 分题即 ±1 分，与教师日常判分容差相当。

**批改输入口径（预注册，防混合口径）**：批改环节的作答文本输入按固定优先级取用——条目**有作业图片且已配置 `ZHIPI_VLM_API_KEY` 时，一律使用机器转写**（`pipeline.ocr.recognize_vlm` 输出，与线上图片批改链路同源，此时一致率如实包含「识别误差 + 批改误差」的叠加）；无图片或识别不可用的条目**回退人工校对转写 `ocr_text_human`**（此时一致率仅度量批改环节，口径天然更宽松）。两类输入的条目**不混合平均**，在 §5 表 B-2 按输入来源分行统计并标注各自样本数；与线上体验对应的主结论以机器转写行为准，人工转写行仅作「批改环节独立能力」的参考。

### 3.3 错因标签命中

AI 错因集合 A（`error_tags` 字段），人工错因集合 H：

```text
Jaccard = |A ∩ H| / |A ∪ H|     （A、H 均为空集时记 1.0：双方都认为无错因，视为一致）
命中率   = |A ∩ H| / |H|         （仅在 H 非空的条目上定义并平均）
```

### 3.4 红黄绿分桶校准（核心证据）

按 AI 输出的分流状态（`status` = green / yellow / red，阈值 85 / 60，口径同设计方案 §9.7 与 `pipeline/confidence.py`）分桶，统计各桶的**教师认可率**：

```text
教师认可 = |s_ai − s_h| ≤ 满分 × 10%       （与 §3.2 一致率同带宽）
桶认可率 = 该桶内被认可条目数 / 该桶条目数
```

分流校准的含义：**绿桶认可率应显著高于黄桶、黄桶高于或近于红桶**——置信度越高的桶教师越认可，红黄绿分流才「名副其实」。绿桶认可率直接回答评委 Q2。

### 3.5 Cohen's kappa（三档等级一致性）

把分数按得分率离散为三档：**优（≥90%）/ 良（70%–90%）/ 需改进（<70%）**（代码常量 `KAPPA_BINS`），对（AI 档位, 人工档位）对计算：

```text
kappa = (Po − Pe) / (1 − Pe)
Po = 观测一致率（混淆矩阵对角线占比）
Pe = 双方档位边缘分布下的期望一致率
```

kappa 扣除了「随机蒙也能蒙对」的部分，比原始一致率更严格。参照常用解读：0.4–0.6 中等、0.6–0.8 高度一致、>0.8 几乎完全一致。

### 3.6 省时率（人工计时，A/B 半分交叉平衡设计，不经 harness）

```text
省时率 = 1 − T_AI辅助 / T_纯人工          （T 均为 A、B 两组合并总用时）
T_纯人工  = A、B 两组「纯人工批改」轮次的教师总用时（含判分、写评语）
T_AI辅助 = A、B 两组「AI 辅助」轮次中教师实际投入的审核用时
           （绿桶抽查 + 黄桶一键确认 + 红桶人工批改 + 修正动作；
            AI 批改的机器时间不占教师，不计入）
```

**交叉平衡设计（预注册）**：将评测卷按学科与卷面档**分层随机对半**分为 A、B 两组（保证两组构成可比）：

- A 组：先**纯人工批改**，隔日再 **AI 辅助批改**；
- B 组：先 **AI 辅助批改**，隔日再**纯人工批改**。

两种模式各在「先做」「后做」的位置上出现一次，第二轮对卷面更熟悉带来的**顺序学习效应在两种模式间对冲抵消**，不再单向利好 AI 辅助模式；组内卷序打乱。由同一名教师执行全部四个轮次，秒表记录，按上式以两组合并用时计算省时率，填入表 F。单教师（n=1）与对半分后单组样本量小的局限保留声明，见 §7。

## 4. 评测流程

```text
① 采集    按 §2.1 拍照 30–50 份 → 存入 eval_set/images/，登记学科与卷面档
② 标注    按 §2.2 完成人工转写、双评判分、仲裁 → 编写 eval_set/manifest.json
③ 配置    设置环境变量 ZHIPI_VLM_API_KEY（OCR + 批改）/ ZHIPI_LLM_API_KEY（批改）
④ 运行    cd demo && python tools/eval_harness.py <eval_set 目录>
⑤ 填表    将生成的 report_tables.md 各表数字填入本文 §5 对应空表，
          report_data.json 归档留证（含逐条明细，供质询时追溯）
⑥ 解读    严格按 §6 预注册规则出结论，不得因结果不理想而临时更换口径
```

脚本自检：`python tools/eval_harness.py --selftest` 用内置模拟数据跑通全流程（运行时显著标注「自测模式……非真实实测」），仅用于验证脚本无 bug，其输出数字**禁止**出现在本文任何结果表中。

## 6. 结果解读模板（预注册规则，数据到位前已定）

以下判读规则与 §3 口径同时预注册。数据填入 §5 后，逐条对号入座，**不得反向挑选对结论有利的规则**：

| # | 预注册规则 | 触发后的动作 |
| --- | --- | --- |
| R1 | **绿桶认可率 ≥ 95%** → 支持「绿色自动通过（教师抽查）」策略按当前阈值（85）上线 | 维持阈值，抽查比例按设计方案执行 |
| R2 | **绿桶认可率 90%–95%** → 绿色策略保留，但属边缘水平 | 上调绿桶强制抽查比例，累积教师修正数据后复评 |
| R3 | **绿桶认可率 < 90%** → 当前绿色阈值过松，「自动通过」宣称不成立 | 上调绿色阈值（如 85 → 90）并复测；复测前对外表述降级为「全部需教师确认」 |
| R4 | **认可率未呈 绿 ≥ 黄 的单调关系** → 置信度公式（§9.7 五因子权重）未校准 | 用实测数据重估因子权重，重跑表 D。**数据循环使用约束**：重估权重使用了本次评测数据，重跑出的分桶表**仅作诊断展示**并显著标注「权重经本数据重估，存在过拟合风险，不作正式结论」；对外正式引用的分桶结论，必须在**留出子集**（重估前预先切出、未参与重估）或**新采集数据**上复测得出 |
| R5 | **总分一致率 ≥ 85% 且 kappa ≥ 0.6** → 支持「可用的辅助批改」定位；**kappa < 0.4** → 不得宣称「接近教师水平」，对外仅表述为「初筛工具」 | 措辞随证据分级 |
| R6 | **mean(AI vs T1 一致率, AI vs T2 一致率) ≥ T1 vs T2 一致率 × 0.9** → 可表述「接近人际一致性水平」；低于该线则不使用此类表述。三个一致率均按同带宽、对**双评原始分**计算（§2.2 第 4 条、表 B）；**不得**以「AI vs 仲裁共识分」的一致率参与本比较——共识分经双评平滑，该口径与原始互评不对称、统计上天然偏向 AI | 以人—人原始互评一致率为参照、两侧口径对称地校准宣称 |
| R7 | **总体 CER ≤ 5%（工整档 ≤ 3%）** → 识别环节达到可用；**CER > 15%** → OCR 是主要瓶颈，表 B/D 结论需在「转写正确子集」上复核后方可引用 | 瓶颈归因先于能力宣称 |
| R8 | **错因平均命中率 ≥ 70%** → 支持错因驱动的学情分析与画像功能；**< 50%** → 错因标签在产品中降级为「仅供教师参考」并如实标注 | 功能宣称随证据分级 |
| R9 | **红桶样本占比 > 40%** → 系统对真实卷面的整体把握不足 | 优先优化识别与预处理，而非放宽阈值「制造」绿桶 |
| R10 | **省时率 ≥ 50%** → 支持「显著减负」宣称；**< 30%** → 对外不使用「大幅省时」表述 | 措辞随证据分级 |
| R11 | **红 / 黄桶中「AI 判低分但教师认可」的条目占该桶 ≥ 1/3**（AI 判低分：AI 得分率 < 70%，同 §3.5「需改进」档；教师认可：\|s_ai − s_h\| ≤ 满分 × 10%——即学生确实答错、AI 判分本身正确，却被置信度压入人工桶）→ 说明 `answer_match` 因子与判分正确性发生**耦合偏差**：该因子本应度量「终答可比对程度」（批改可信度），其冷启动实现在学生真实答错时会同步走低（概念边界见技术文档 §6.3），把「答错但判对」的作答误压入红 / 黄 | 将 `answer_match` 因子与判分结果**解耦分析**：按「学生答对 / 答错」分层重算各桶认可率，**单独成表报告**，不与表 D 主口径混合；据此评估以与对错无关的「终答可辨识度」类度量替换该因子的必要性 |

## 7. 局限性声明

即使全部指标达标，本评测的证明力也有明确边界，主动声明如下：

1. **样本量小**：30–50 份总量下，分桶后单桶可能仅 10–20 条，比例类指标的 95% 置信区间宽达 ±10–20 个百分点。本评测定位为**小规模先导评测（pilot）**，结论表述一律附样本量，不做过度外推。
2. **非随机抽样**：评测卷来自团队可触达的班级（便利样本），学校 / 教师 / 学生分布单一，不代表全体初中学情；卷面三档为人工配比而非自然分布。
3. **模拟数据严格隔离**：Demo 内置的 `submissions.json` 预置标注、`history.json` 模拟历史学情、`--selftest` 输出，均**不参与**本评测，任何模拟数字不进入 §5。
4. **人工参照并非金标准**：人工判分本身存在评分者差异（§2.2 双评一致率即为其度量），「一致率」衡量的是与人工判分的接近程度，不等于绝对正确。
5. **参照判分者为团队成员而非在职教师**：双评者（§2.2）为团队成员，虽依 Rubric 逐步校准后独立判分，但不具备一线教师的判分经验与班级语境，本评测的「AI—教师一致率」严格说是「AI 与依 Rubric 判分的团队成员的一致率」，解释与对外表述需谨慎；如后续获得在职教师参与判分，其结果将**单独标注为教师参照行**报告，不与团队成员参照混合。
6. **单时点单模型**：结果绑定 §5 运行环境记录中的模型与日期；模型供应商升级后指标可能漂移，上线后需以教师修正回流数据（设计方案 §10.1）做持续监控，而非一测定终身。
7. **省时评测的混杂因素**：§3.6 的 A/B 半分交叉设计已在两种模式间对冲顺序学习效应，但仍为单教师计时（n=1），且对半分后每组仅 15–25 份，疲劳、组间残余难度差等混杂无法完全排除，计时结果仅具量级参考价值。
8. **一致 ≠ 教学有效**：本评测不涉及「使用系统后学生成绩是否提升」这一最终教育效度问题，该问题需更长周期的对照研究。
