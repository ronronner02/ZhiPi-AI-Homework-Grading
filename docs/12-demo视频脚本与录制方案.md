# 12 · demo 展示视频脚本与录制方案（3–5 分钟）

> 目标时长 **4 分 20 秒**（落在赛事要求的 3–5 分钟中部，留 40 秒剪辑余量）
> 适用：40 强赛提交材料 §2.5「demo 展示视频」｜配套素材见 `docs/assets/`
>
> **一条自律（与主文档一致）**：视频只演示**【已实现】**的功能；模拟数据、演示模式、加速剪辑**必须在画面上标注**。我们不在视频里把设计说成已实现，也不拿假结果冒充跑通。

---

## 一、这支视频要回答的问题

评委看完 4 分钟，应该能回答：

1. 它**真的能跑**吗？——全程真实链路、真实作业照片、真实耗时。
2. 它比"批得快"的工具**多做了什么**？——过程级证据链 + 错因诊断 + 教师可控分流 + 教学闭环。
3. 老师**凭什么敢用**？——转写可见可改、每步判分有 evidence、红黄绿分流、终审回灌。
4. 它**哪里不行**？——潦草选择题无自动解，我们主动说。

**贯穿主线（每个镜头都往这句话上收）**：
> 普通 AI 批改回答"这道题对不对"；智批π 回答"学生为什么错、错在哪一步、老师敢不敢信这个判断、下一步怎么补"。

## 二、交付规格

| 项 | 规格 |
|---|---|
| 分辨率 / 帧率 | 1920×1080 · 30fps（屏幕内容为主，30fps 足够且文件更小） |
| 浏览器窗口 | 1440×900，系统缩放 100%，浏览器缩放 100% |
| 字幕 | **全程硬字幕**（评委很可能静音看）｜关键数字加角标 |
| 音频 | 口播单独录（避免键盘声）；背景音乐音量 ≤ −24dB 或不加 |

| 发布 | 飞书妙记（可生成分享链接）或 B 站，链接回填主文档 §2.5 |

## 三、分镜脚本

> 表内「兜底」列是**防翻车预案**——每个镜头都要想好失败时怎么办，不要在录制当天临场想。

### S1 · 开场：问题（0:00–0:22）

| 项 | 内容 |
|---|---|
| **画面** | 纸底文字动画：教师周三晚上的时间轴（21:00 收上 40 份 → 23:30 判完 → 学情分析归零）。可直接用 `docs/assets/` 的视觉风格做一张静态卡 + 缓推。 |
| **字幕** | 「一个班 40 份作业 · 判分 150 分钟 · 评语只剩"继续加油" · 学情分析根本没发生」 |
| **口播** | 一个班四十份作业，每份都要判对错、写评语、分析薄弱点。老师九点开始判，十一点半判完——此时留给评语的时间只够写"继续加油"，留给学情分析的时间是零。批得快的工具已经很多，但没有一个解决了真正的问题：**老师不敢把判分权，交给一个不知道什么时候会错的黑盒。** |
| **兜底** | 纯素材镜头，无风险。 |

### S2 · 教师答案页建题库（0:22–1:00）

| 项 | 内容 |
|---|---|
| **画面** | 「拍照提交」页 → 上传目标切到**教师答案页** → 拖入答案页照片 → 逐题抽出 `{题号,题干,标准答案,题型,分值}` → 镜头推近**「系统推定」**标记 → 当场改一个分值 |
| **字幕** | 「教师答案页 → 会话题库」「卷面没印分值 → 按题型推定 · **教师可改**」 |
| **口播** | 真实作业几乎必然在任何预置题库之外，所以我们让老师把答案页直接拍进来。系统逐题抽出题干、标准答案、题型和分值，建成本次会话的题库。卷面上没印分值的题按题型推定，界面**明确标注"系统推定"，老师可以逐题改**，改完自动重建这道题的评分 Rubric。 |
| **兜底** | 若建库超时：改用已建好的题库（提前建好一份同名会话），画面从题库列表进入，口播不变。 |

### S3 · 三阶段识别与可编辑转写（1:00–1:50）

| 项 | 内容 |
|---|---|
| **画面** | 上传目标切到**学生页** → 拖入学生作业照片 → 识别进行中 → **转写文本面板**（逐题）→ 光标点进去**直接改一个字**（演示可编辑）→ 指出「越界作答」那段被归属回原题 → 指出分式那题标着**「已修正 · 待复核」** → 点一次**「强模型重读」** |
| **字幕** | 「LAYOUT 定位 → ATTRIBUTION 按内容归属 → REFINE 裁图放大复识」「转写：教师可见 · 可编辑 · 可复识」 |
| **口播** | 学生页上传后，识别不是一次 OCR，而是三个阶段：先只定位这一页有哪些题、哪些手写块；再**按内容对应**决定每块属于哪道题——学生写不下写到旁边空白处的那一整段，就是靠这一步跨区域捡回来的；最后对可疑的题裁图放大、单独再问一次。学术实证说，视觉大模型的评分错误里约**八成七源于转写失败**，不是评分逻辑错——所以我们把冗余放在转写层。**你现在看到的转写文本可以直接改**，这是我们留给老师的第一道防线。 |
| **兜底** | ① 识别失败：页面会**明确提示识别不可用**（不伪造降级），此时切镜到已批改好的结果页，口播接"我们提前批好的这一份"；② 日配额用尽：同上；③ **不要**在这一段加速——耗时本身是卖点。 |

### S4 · 整页批改与过程级证据链（1:50–2:40）

| 项 | 内容 |
|---|---|
| **画面** | 点**「批改整页」** → 计时可见 → 结果页顶部**批改痕迹图**（学生原卷叠加 ✓ / 半勾 / ✗ + 得分 + 页顶总分栏）→ 点**下载** → 下滑展开某道过程题：Rubric 逐节点 + 每步 `evidence` 引用原文 + 十类错因标签 + 个性化评语 |
| **字幕** | 「整页一次批完 · 实测 8 题 23 秒」「每步判分附 evidence：引用的就是卷面那行 x=2」「6 / 10 —— 给过程分，不是"答案不全判 0"」 |
| **口播** | 整页一次批完，实测数学卷八道题二十三秒。最上面是批改痕迹图——批改结果直接叠在学生原卷上，可下载可打印。往下每一道题都能展开：解法选择、因式分解、求根、结论，**每一步判分都带 evidence，引用的就是卷面上那一行**。这道题学生只写了 x 等于 2，漏了一个根，我们**给过程分**：对的两步全给，漏根那步保留部分分，只在真正错的那步扣到底，六分。同时给两层错因：知识点，加十类枚举里的"步骤缺失"。 |
| **兜底** | 若批改耗时明显长于文档实测：**保留真实耗时**，字幕注明当次网络条件；若剪掉等待，必须打字幕「已加速 ×N」。 |

### S5 · 红黄绿分流与教师终审回灌（2:40–3:20）

| 项 | 内容 |
|---|---|
| **画面** | 结果页**置信度五因子明细**（逐项展开）→ 切「教师工作台」→ 红黄绿队列 → 打开一份黄桶 → 改分 / 改错因 / 改评语 → 提示**该题教师通过率回灌** |
| **字幕** | 「五因子加权 · 测不出的重归一化剔除」「三条后置防线：不占权重，只做否决」「≥85 绿 · 60–85 黄 · <60 红」 |
| **口播** | 每一份都带置信度五因子明细：识别清晰度、答案匹配度、Rubric 覆盖度、二次批改一致性、历史教师通过率。**测不出的因子按权重重归一化剔除，不当零分白扣。** 分数落进红黄绿三桶，老师只精改黄红桶、抽查绿桶。另外还有三条后置防线，它们**不参与打分，只负责否决**——双模型交叉验证分差超过满分百分之十五，一票否决转人工。而老师的每一次终审，都会**反向校准这道题以后的可信度**。 |
| **兜底** | 工作台数据为空：先在录制前跑一批（≥6 份）铺满队列。 |

### S6 · 班级看板与讲评课件大纲（3:20–3:55）

| 项 | 内容 |
|---|---|
| **画面** | 「班级看板」→ 薄弱点 KPI / 知识点错误率 / 错因分布 / 红黄绿占比 → 点**生成讲评课件大纲** → Markdown 大纲 → **复制大纲** |
| **字幕** | 「批改数据的终点不是分数，是下一节课」「共性错因 + 匿名典型错例 + 分层任务 + 5 分钟复测」 |
| **口播** | 一次批改如果只产出分数，价值在交卷那一刻就结束了。我们把它继续往下推：班级薄弱点、错因分布、学生长期错因画像，再到**一键生成的讲评课件大纲**——共性错因、匿名典型错例、分层任务、五分钟复测，复制出来就能粘进希沃白板或者飞书文档当备课底稿。 |
| **兜底** | **若镜头扫到学生画像的历史时间线，字幕必须同时打出「历史时间线为模拟数据」**（界面本身已标注，不要剪掉那个标注）。 |

### S7 · 飞书协同（3:55–4:20）

| 项 | 内容 |
|---|---|
| **画面** | 点**推送飞书** → 飞书里收到审核卡片（红黄绿统计 + 待处理数 + 跳转按钮）→ 点**同步台账** → 多维表格逐行写入 → **AI 字段**自动生成错因摘要与学习建议 |
| **字幕** | 「多维表格 + AI 字段捷径」「机器人互动卡片」「live 需凭据 · 未配置时为演示模式」 |
| **口播** | 批改在系统，协同在飞书。批完即刻推送教师待审卡片，红黄绿统计和待处理数一目了然，点一下跳回工作台。逐题结果写进多维表格的学情台账，**AI 字段逐行自动生成一句话错因摘要和个性化学习建议**，仪表盘直接出班级薄弱点。没配凭据时是演示模式，任何网络或鉴权异常都会自动降级——**现场演示不会中断**。 |
| **兜底** | 无凭据 / 推送失败：直接展示**演示模式**画面，字幕注明「演示模式 · 未配置凭据」，**不要**剪成像是 live 成功。 |

### S8 · 收尾：我们解决不了什么（4:20–4:40）

| 项 | 内容 |
|---|---|
| **画面** | 切到 `docs/assets/f3-failures.png`（四类转写失败图）→ 停在第 04 张卡「目前无自动解」→ 定格金句卡 |
| **字幕** | 「学生写 D，模型读 B；独立复识 5 次全错，每次 confidence=1.0」「自报置信度 / 多读一致性 / 双模型交叉验证 —— 对这一类全部失效」 |

## 四、口播逐字稿（连读版 · 约 1050 字 / 约 4 分 05 秒）

> 语速按 **4.2–4.5 字/秒**（清晰讲解速度）。录完先自己掐表，超过 4 分 45 秒就删 S2 或 S6 的一句。

一个班四十份作业，每份都要判对错、写评语、分析薄弱点。老师九点开始判，十一点半判完——此时留给评语的时间只够写"继续加油"，留给学情分析的时间是零。批得快的工具已经很多，但没有一个解决了真正的问题：老师不敢把判分权，交给一个不知道什么时候会错的黑盒。

真实作业几乎必然在任何预置题库之外，所以我们让老师把答案页直接拍进来。系统逐题抽出题干、标准答案、题型和分值，建成本次会话的题库。卷面上没印分值的题按题型推定，界面明确标注"系统推定"，老师可以逐题改，改完自动重建这道题的评分 Rubric。

学生页上传后，识别不是一次 OCR，而是三个阶段：先只定位这一页有哪些题、哪些手写块；再按内容对应决定每块属于哪道题——学生写不下写到旁边空白处的那一整段，就是靠这一步跨区域捡回来的；最后对可疑的题裁图放大、单独再问一次。学术实证说，视觉大模型的评分错误里约八成七源于转写失败，不是评分逻辑错——所以我们把冗余放在转写层。你现在看到的转写文本可以直接改，这是我们留给老师的第一道防线。

整页一次批完，实测数学卷八道题二十三秒。最上面是批改痕迹图——批改结果直接叠在学生原卷上，可下载可打印。往下每一道题都能展开：解法选择、因式分解、求根、结论，每一步判分都带 evidence，引用的就是卷面上那一行。这道题学生只写了 x 等于 2，漏了一个根，我们给过程分：对的两步全给，漏根那步保留部分分，只在真正错的那步扣到底，六分。同时给两层错因：知识点，加十类枚举里的"步骤缺失"。

每一份都带置信度五因子明细：识别清晰度、答案匹配度、Rubric 覆盖度、二次批改一致性、历史教师通过率。测不出的因子按权重重归一化剔除，不当零分白扣。分数落进红黄绿三桶，老师只精改黄红桶、抽查绿桶。另外还有三条后置防线，它们不参与打分，只负责否决——双模型交叉验证分差超过满分百分之十五，一票否决转人工。而老师的每一次终审，都会反向校准这道题以后的可信度。

一次批改如果只产出分数，价值在交卷那一刻就结束了。我们把它继续往下推：班级薄弱点、错因分布、学生长期错因画像，再到一键生成的讲评课件大纲——共性错因、匿名典型错例、分层任务、五分钟复测，复制出来就能粘进希沃白板或者飞书文档当备课底稿。

批改在系统，协同在飞书。批完即刻推送教师待审卡片，红黄绿统计和待处理数一目了然，点一下跳回工作台。逐题结果写进多维表格的学情台账，AI 字段逐行自动生成一句话错因摘要和个性化学习建议。没配凭据时是演示模式，任何网络或鉴权异常都会自动降级，现场演示不会中断。

最后必须说清楚我们解决不了什么。有一道潦草的选择题，学生写的是 D，模型读成 B；我们裁图放大、独立复识五次，五次全是 B，而且每一次都报字迹清晰、置信度百分之百。我们试过的所有检测手段对这一类全部失效。所以我们的处置是：不再往上加检测层，换强模型档位，并且把"教师看转写"这条路留死。一个 AI 系统真正的成熟度，不在于它宣称能解决什么，而在于它知道自己解决不了什么，并且把那部分明确交还给人。

## 五、录制前 checklist（「成功展示」靠这张表，不靠运气）

**环境**

- [ ] `curl http://<host>/api/demo/config` 确认 **`mode=llm`**（不是 mock）——配了密钥 ≠ 生效，进程先启动、`.env` 后修改会静默用旧档位
- [ ] 启动横幅确认当前模型档位与预期一致
- [ ] VLM **日配额余量 ≥ 20 次**（录制会重录，别录到一半额度用尽）
- [ ] 浏览器：**无痕窗口**、关闭翻译/广告插件（插件会改文案）、隐藏书签栏、窗口固定 1440×900
- [ ] 系统：勿扰模式、关闭消息通知、桌面无私人图标、任务栏无红点
- [ ] 断网预案：前端零外部请求，断网仍可展示批改结果 / 教师工作台 / 班级看板三屏

**数据**

- [ ] 演示用**内置真实作业样例**（已遮盖姓名学号）；**不要**临时拿带学生真实信息的卷子
- [ ] 提前跑一批（≥6 份）铺满教师工作台队列与班级看板
- [ ] 提前建好一份同名会话题库作为 S2 的兜底
- [ ] 飞书：若走 live，提前验证 Webhook 与多维表格写入权限；否则明确走演示模式

**流程**

- [ ] **分段录制**，每段独立可重录；不要一镜到底
- [ ] 每段开录前默数 2 秒、结束后停 2 秒，留剪辑余量
- [ ] 鼠标移动放慢，点击前停顿 0.5 秒（观众要跟得上）
- [ ] 关键数字出现时不要立刻切镜，停 1.5 秒

## 六、诚实红线（剪辑时逐条核对）

| 红线 | 具体要求 |
|---|---|
| 只演示已实现 | 知识问答 / Aily 讲评助手、文档 AI 润色为**【设计完成】**，**不进视频**（或明确字幕标注"设计完成，尚未实现"） |
| 模拟数据必标 | 学生画像的**历史时间线为模拟数据**，界面标注不要被裁掉，字幕同步说明 |
| 演示模式必标 | 飞书未配凭据时，字幕注明「演示模式 · 未配置凭据」，不得剪成 live 成功 |
